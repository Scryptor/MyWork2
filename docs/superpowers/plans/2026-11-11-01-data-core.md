# План 1. Основа данных — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** git-репозиторий с Rust-воркспейсом и CI на трёх ОС, в котором доменные правила, схема БД и
прикладные сервисы (справочники, статусы, точки, настройки, клиенты, заказы, пользователи и вход,
журнал) работают одинаково на SQLite и PostgreSQL и покрыты тестами.

**Architecture:** три крейта. `mw-domain` — чистые правила без ввода-вывода (деньги, поиск, телефоны,
штрихкоды, статусы, права). `mw-db` — SeaORM-сущности, одна портируемая миграция со стартовыми данными,
подключение и тестовые помощники. `mw-core` — структура `Core` с асинхронными методами: каждый метод
проверяет права `Actor`, пишет изменения и запись журнала в одной транзакции. HTTP-слоя здесь нет, его
добавит план 2 поверх `Core`.

**Tech Stack:** Rust 1.95 (edition 2024), SeaORM 2.0 + sea-orm-migration 2.0 (sqlx: SQLite и PostgreSQL),
tokio, chrono + chrono-tz, argon2, sha1, sha2, serde, thiserror.

**Spec:** `docs/superpowers/specs/2026-11-11-mywork3-crossplatform-design.md` (разделы 2, 3, 4, 4.2, 5, 7, 8)
и `docs/legacy/mywork2-analysis.md`. Дорожная карта всех планов: `docs/superpowers/plans/README.md`.

## Review Focus

1. **Одновременная правка.** Два рабочих места сохраняют один и тот же заказ или клиента со старой версией. Второе сохранение должно получить `Conflict { current_version }`, а правки первого не должны потеряться. Тесты: задачи 9 и 11.
2. **Поиск.** «ПЁТР» находится по «петр», «ё» равно «е»; несколько слов из разных полей («петров a52») работают; `%`, `_`, `'` ищутся буквально, а не как шаблоны; пустой запрос не падает. Тесты: задачи 3 и 12.
3. **Телефон в любом виде.** `+7 (921) 123-45-67`, `8 921 123 45 67` и `9211234567` находят одного и того же клиента — и в клиентах, и в заказах. Тесты: задачи 3, 9, 12.
4. **Деньги из ручного ввода.** `6 500`, `6500,50`, `6 500 ₽` дают точные копейки; `6500.555`, `-100`, `abc` дают понятную ошибку, а не округление или панику. Тесты: задача 2.
5. **Последний администратор.** Нельзя отключить, понизить или лишить права `users_manage` последнего активного пользователя с этим правом, иначе в программу больше никто не войдёт. Тесты: задача 13.

## Решения этого плана (уточнения спеки)

- **Один журнал вместо двух таблиц.** Спека 7 называет `order_status_history` и `audit_log`; здесь только `audit_log`. История заказа — это записи журнала с его `order_id`. План 3 переносит туда и старые `StatesMap`, и `HistoryBD`.
- **Индексы.** Поиск по подстроке (`LIKE '%…%'`) индекс не использует; на десятках тысяч заказов это миллисекунды. Индексы есть у `phone_key`, `barcode`, внешних ключей и дат.
- **Сортировка по ФИО** идёт по `clients.search_text`. Строчная кириллица после замены `ё→е` уже упорядочена по алфавиту, поэтому отдельная collation не нужна.
- **PostgreSQL в тестах** подключается через `MW_TEST_PG_URL` (в CI — service-контейнер `postgres:17` на ubuntu), без testcontainers: на macOS- и Windows-раннерах GitHub нет Docker.
- **«В сервисе»** означает «статус не вида `issued`», а не «нет даты выдачи», как было в MyWork 2. Так заказ, принятый по гарантии после выдачи, снова виден в сервисе. `issued_at` хранит дату первой выдачи и при повторной выдаче не меняется.
- **Ориентировочная стоимость** — диапазон `estimate_from`/`estimate_to`, как в одобренном макете приёма.
- **Телефон.** Хранятся цифры как ввели (`phone`) и ключ сравнения `phone_key` — последние 10 цифр. Поэтому `+7…`, `8…` и номер без кода совпадают.
- **Права.** Список прав — 16 флагов `GroupDostup` без SMS, плюс новые `clients_edit`, `users_manage`, `audit_view`. Заказы может смотреть любой вошедший пользователь, как в MyWork 2.
- **Стандартная гарантия** (настройка `default_warranty_days`) только подставляется интерфейсом в форму приёма; `Core` её не применяет.
- **Следы импорта** (`legacy_raw`, таблица трек-номеров) добавит план 3 отдельной миграцией. Схема этого плана их не содержит.

## Схема БД (миграция `m20261111_000001_init`)

Общие правила: `id` — `BIGINT` автоинкремент, первичный ключ (в SQLite — `INTEGER PRIMARY KEY AUTOINCREMENT`).
Время — `TIMESTAMP` без пояса (в SQLite — TEXT). Деньги — `BIGINT` в копейках. Флаги — `BOOLEAN NOT NULL DEFAULT false`.
Текстовые поля без значения — `TEXT NOT NULL DEFAULT ''`. Схема строится через построитель SeaQuery, без сырого SQL под одну СУБД.

| Таблица | Колонки (кроме `id`) | Ограничения и индексы |
|---|---|---|
| `service_points` | `name`, `sort_order INT NOT NULL DEFAULT 0`, `archived` | UNIQUE(`name`) |
| `statuses` | `name`, `kind` (`open` / `diagnostics` / `ready` / `issued`), `color`, `sort_order INT`, `archived` | UNIQUE(`name`) |
| `dictionary_items` | `kind`, `value`, `sort_order INT NOT NULL DEFAULT 0` | UNIQUE(`kind`, `value`) |
| `clients` | `full_name`, `phone`, `phone_key`, `address`, `note`, `source`, `blacklisted`, `created_at`, `updated_at` (NOT NULL), `deleted_at` (NULL), `version BIGINT NOT NULL DEFAULT 1`, `search_text` | INDEX(`phone_key`) |
| `orders` | `client_id` → clients (RESTRICT), `service_point_id` NULL → service_points (RESTRICT), `status_id` → statuses (RESTRICT), `received_at` NOT NULL, `issued_at` NULL, `prepaid_at` NULL, `device_type`, `brand`, `model`, `serial`, `color`, `device_password`, `completeness`, `device_condition`, `malfunction`, `work_done`, `internal_comment`, `master`, `barcode`, `estimate_from` / `estimate_to` / `final_price` (BIGINT NULL), `prepayment` / `extra_costs` / `discount` (BIGINT NOT NULL DEFAULT 0), `warranty_days INT NULL`, `need_call`, `need_parts`, `created_at`, `updated_at`, `deleted_at`, `version`, `search_text` | INDEX(`client_id`), INDEX(`status_id`), INDEX(`barcode`), INDEX(`received_at`) |
