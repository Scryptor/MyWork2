# План 2. HTTP API и сервер — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** HTTP API поверх `mw-core` на Axum — вход по токену, режим без входа только на 127.0.0.1, ограничение
попыток входа, единые ошибки на русском, OpenAPI и TS-типы с проверкой актуальности — и бинарник `mw-server`,
который настраивается, мигрирует базу и корректно останавливается. Всё проверено на SQLite и PostgreSQL.

**Architecture:** сначала доводится ядро: отдельная внутренняя ошибка, закрытый `Actor`, ограничение
одновременных вычислений Argon2, единое правило пустых правок; на типы домена и ядра добавляются `serde`,
`ts_rs::TS` и `utoipa::ToSchema` — они и есть типы API. Новый крейт `mw-api` — Axum-роутер: пользователь из
`Authorization: Bearer`, режим без входа, ограничитель попыток, слои защиты, по модулю обработчиков на раздел и
контракт (`openapi.json` + `bindings/*.ts`), который тест сверяет с кодом. Новый крейт `mw-server` — библиотека
(конфигурация, папка данных, запуск, остановка, создание администратора) и тонкий бинарник; ту же библиотеку в
плане 5 возьмёт десктоп.

**Tech Stack:** Rust 1.95 (edition 2024), axum 0.8, axum-extra 0.12 (`Query` с повторяющимися параметрами),
utoipa 6 + utoipa-axum 0.3 (OpenAPI 3.1), ts-rs 12, tokio, tracing + tracing-subscriber, clap 4, dirs,
rpassword, iana-time-zone, url; SeaORM 2.0 из плана 1.

## Review Focus

1. **«Не передано» против `null` в правках.** `{}` ничего не меняет, `{"estimate_from": null}` очищает сумму, `{"brand": null}` и опечатка в имени поля дают 400, а не молчаливое «ничего не изменилось». Тесты: задачи 4 и 10.
2. **Два рабочих места правят одно и то же по HTTP.** Устаревшая `version` в правке, которая что-то меняет, → 409 с `current_version`, первая правка цела; правка без изменений с устаревшей версией → 200 без новой версии и без записи в журнал. Тесты: задачи 3, 9, 10.
3. **Подбор пароля.** Шестая неверная попытка для одного логина, двадцать первая с одного адреса и подбор текущего пароля через смену пароля дают 429 с `Retry-After`; во время блокировки не проходит и верный пароль; через 15 минут вход снова работает. Тесты: задача 7.
4. **Режим без входа утекает в сеть.** Сервер не на 127.0.0.1 без пользователей не пускает без входа; чужая страница в браузере не может изменить данные локального сервера (нет `Content-Type: application/json`) и не может обратиться к нему под чужим именем хоста (DNS rebinding). Тесты: задачи 5 и 7.
5. **Секреты и персональные данные в логах.** Верные и неверные пароли, токены, пароль в адресе PostgreSQL, строки поиска (`?query=`, `?phone=`) не появляются в выводе логов сервера. Тесты: задачи 7 и 12.

## Решения этого плана

- **Типы API — типы ядра.** Отдельных DTO-копий нет: `mw-domain` и `mw-core` выводят `Serialize`/`Deserialize`, `ts_rs::TS` и `utoipa::ToSchema` на свои типы. `mw-api` добавляет только типы самого HTTP: вход, параметры запросов, страницы, ошибки. Любое изменение формы API видно в диффе `openapi.json` и `bindings/`, а тест `contract` не даёт им отстать от кода. Атрибут `#[ts(export)]` не используется: TS выгружает только `mw-api`.
- **Правки (`…Patch`).** Поле не передано — не менять. `null` разрешён только у полей, которые бывают пустыми (`Option<Option<T>>`), и очищает их. `null` у остальных полей и неизвестные поля → 400. В TS это `field?: T` и `field?: T | null`, в OpenAPI — необязательное поле, `nullable` только у очищаемых. Реализация — два десериализатора `mw_core::patch::{present, nullable}`.
- **Входные типы строгие:** `#[serde(deny_unknown_fields)]` на всех телах и параметрах запросов; у `New…` поля обязательны, как в TS.
- **Версия записи** для изменения заказов, клиентов, пользователей и ролей передаётся параметром `?version=N` (PATCH, DELETE, действия над заказом). Тело правки — ровно `…Patch`.
- **Единое правило пустых правок.** Порядок в каждом методе изменения: права → существование записи → различия. Различий нет — успех с текущим состоянием: без новой версии, без записи в БД и в журнал, и версия не проверяется (ничего не перезаписывается — значит, и потерять нечего). Различия есть — проверка версии (`Conflict`), затем проверки значений, затем запись и журнал только с изменившимися полями. Сравнение — после той же нормализации, что и при записи (обрезка пробелов). Перестановка в прежнем порядке — тоже пустая правка. Смена пароля правкой не считается.
- **Вход — токен в заголовке** `Authorization: Bearer <64 hex>`, без cookie: окно Tauri и сервер на 127.0.0.1 — разные источники, а заголовок браузер сам не подставляет, поэтому CSRF против токена невозможен.
- **Режим без входа** (как в MyWork 2: нет активных пользователей — нет входа) действует, только если сервер слушает loopback-адрес и в базе нет активных пользователей: запрос без токена выполняется от `Actor::unrestricted("Без входа")`. Запрос с токеном всегда проверяется по токену. На сетевом адресе без пользователей — только 401; первого администратора создаёт `mw-server create-admin`.
- **Защита локального сервера от браузера.** Изменяющие методы (POST, PUT, PATCH, DELETE) принимаются только с `Content-Type: application/json`: такой запрос с чужого сайта браузер не отправит без разрешения CORS. Сервер на loopback-адресе принимает только `Host` `127.0.0.1`, `localhost` и `[::1]` с любым портом (защита от DNS rebinding). CORS не включается — разрешённые источники Tauri добавит план 5.
- **Ограничение попыток** — в памяти `mw-api`, окно 15 минут от первой неудачи: 5 неудач на логин (или на пользователя при смене пароля) и 20 неудач с одного IP. Во время блокировки пароль не проверяется (и Argon2 не нагружается), ответ 429 с `Retry-After`. Успешный вход сбрасывает счётчик логина. После перезапуска сервера счётчики пусты.
- **Argon2** — не больше `MAX_CONCURRENT_PASSWORD_HASHES = 4` вычислений одновременно на `Core` (≈19 МиБ каждое). Разрешение семафора переходит внутрь блокирующей задачи и освобождается только по её завершении, даже если клиент уже отключился.
- **Ошибки API** — всегда JSON `ErrorBody { code, message, fields, current_version, permission, retry_after_secs }`, `message` по-русски; таблица соответствия — в задаче 5. Детали внутренних ошибок пишутся только в лог сервера.
- **Внутренняя ошибка** — `CoreError::Internal(String)` вместо `CoreError::Db(DbErr::Custom)`: повреждённые коды в БД, сбой хэширования, нет случайных байтов. `CoreError::Db` остаётся для ошибок самой СУБД.
- **`Actor` закрыт:** поля приватные, чтение через методы. Получить `Actor` можно только через `Core::authenticate` или `Actor::unrestricted` (режим без входа, консоль сервера). `Actor::for_tests` и `Core::db()` существуют только с фичей `testing`, которую включают dev-зависимости; шаг CI `cargo check --workspace` не даёт рабочему коду ими пользоваться.
- **Логи запросов** — метод, путь без строки запроса, код ответа, длительность. Заголовки, параметры и тела не пишутся. Ответы API получают `Cache-Control: no-store` и `X-Content-Type-Options: nosniff`.
- **Лимиты запроса:** тело до 1 МиБ, обработка до 30 с (дольше → 503 `unavailable`).
- **`mw-server`:** по умолчанию слушает `127.0.0.1:8080`, база — SQLite `mywork.db` в папке данных. Папка данных — `--data-dir`/`MW_DATA_DIR`, иначе `data` рядом с программой при наличии `portable.txt`, иначе папка данных ОС + `MyWork3` (спека, «Где лежат данные»). Миграции применяются при запуске; база от более новой версии программы (в ней есть неизвестная миграция) — отказ запуска, база не меняется. Остановка — Ctrl+C или SIGTERM: новые соединения не принимаются, начатые запросы завершаются, пул БД закрывается.
- **TS-типы** лежат в `crates/mw-api/bindings/` (по файлу на тип, `i64` → `number`: суммы и id меньше 2⁵³); откуда их возьмёт интерфейс, решит план 5.
- **Даты в OpenAPI** utoipa помечает `format: date-time`, хотя смещения в них нет; это сказано в описании API.
- **Вне этого плана:** WebSocket и поиск в сети, HTTPS и закрепление сертификата, доверенные прокси (план 9); CORS для Tauri, раздача интерфейса, логи в файл (план 5); вложения и файлы (планы 5 и 10).

fn check_patch<T>() where T: DeserializeOwned + TS + utoipa::ToSchema + Default + PartialEq + Debug {
    let name = <T as utoipa::ToSchema>::name();
    let schema = serde_json::to_value(<T as utoipa::PartialSchema>::schema()).unwrap();
    let decl = T::decl(&cfg());
    let props = schema["properties"].as_object().unwrap();
    assert!(!props.is_empty(), "{name}");
    assert_eq!(schema["additionalProperties"], json!(false), "{name}");
    assert!(schema.get("required").is_none(), "{name}: у правки нет обязательных полей");
    for (field, prop) in props {
