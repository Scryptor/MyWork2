# План 5.7. Замечания автора: интерфейс — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** закрыть замечания автора по интерфейсу после первого запуска программы для компьютера на его базе
(«Замечания автора по программе для компьютера» в `docs/superpowers/plans/README.md`), кроме мастеров и ролей (план 5.8)
и карточки заказа (план 5.9).

**Architecture:** четыре задачи по областям: оболочка и список заказов; общий компонент подсказок; настройки
(часовой пояс, гарантия, строки статусов, точек и справочников); отчёт импорта. Поведение сервера меняется только в
отчёте импорта (записи групп без заказов) — с перегенерацией контракта.

**Tech Stack:** Rust (Axum 0.8, SeaORM 2), SvelteKit 3 SPA, Svelte 5 (руны), Vitest, Playwright; программа для
компьютера — Tauri 2 (WKWebView на macOS).

**Spec:** `docs/superpowers/specs/2026-11-15-ui-design-system-design.md` (компоненты, токены, раздел 11 — решения),
основная спека `docs/superpowers/specs/2026-11-11-mywork3-crossplatform-design.md`; источник пунктов — README,
«Заметки → Замечания автора…».

## Global Constraints

- Всё из `AGENTS.md`: токены вместо литералов, ширины — только `display`/`data-width`, руны, `#lib/...` с
  расширениями, тексты в `ru.ts`, иконки `@lucide/svelte` по одной, новые компоненты — в `#lib/ui` с разделом на
  витрине `/design`, e2e в Chromium и WebKit на настоящем сервере с `uniq()`; общие e2e-серверы — встроенные статусы и
  справочники не трогать, глобальные настройки возвращать.
- Перед коммитом зелёное: Rust — `cargo fmt --all --check && cargo clippy --workspace --all-targets -- -D warnings &&
  cargo check --workspace && cargo test --workspace` (и с `MW_TEST_PG_URL`); интерфейс — `cd apps/ui && npm run verify
  && npm run test:e2e`; при смене API — контракт (`MW_UPDATE_CONTRACT=1 …`); при смене зависимостей `crates/*` —
  `apps/desktop/src-tauri/Cargo.lock`.
- Никогда не запускать ничего на `~/Library/Application Support/MyWork3*` и не открывать программу из `/Applications`:
  там настоящая база автора. Реальные данные клиентов — нигде.
- Каждый закрытый пункт удаляется из «Замечания автора…» в README в той же задаче.
- Коммиты по-русски `fix(…)/feat(…)/test(…)/docs:`, последняя строка `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. Масштаб 1,5 и ширина xs: подсказки, строки статусов, поле поиска в верхней панели, чип «Выданные» — ничего не
   вылезает и не наезжает (обход экранов `layout.spec.ts`).
2. Только клавиатура: значок подсказки достигается Tab, открывается Enter/Space, Esc закрывает и возвращает фокус на
   значок; однобуквенные клавиши при открытой подсказке не срабатывают.
3. Сохранённый часовой пояс или гарантия по умолчанию, которых нет в списке, остаются видны и выбраны; другой выбор
   сохраняется; пустая гарантия допустима.
4. Группа отчёта с тысячами предупреждений открывается без подвисания: записи ограничены, честно сказано, сколько
   показано из скольких.
5. В окне программы на macOS (WKWebView) выпадающие списки, окно подсказки и переход из отчёта к заказу работают так
   же, как в браузере (e2e WebKit).

4. **Нестабильный тест.** `e2e/login.spec.ts:462` («a tab signed in without «Запомнить» is reset…») один раз упал в

### Task 3: Настройки — часовой пояс, гарантия, строки статусов, точек и справочников

**Files:** `apps/ui/src/lib/settings/timezones.ts` (+ тест), `apps/ui/src/lib/ui/Select.svelte` (группы),
`apps/ui/src/routes/(app)/settings/{general,orders,statuses,points,dictionaries}/+page.svelte`,
`apps/ui/src/lib/settings/{CatalogRows.svelte,status-kind.ts}`, `apps/ui/src/lib/i18n/ru.ts`, e2e настроек и
`layout.spec.ts`.

**Interfaces:**
- Consumes: `HelpHint`/проп `help` (Task 2).
- Produces: `timezoneOptions(now: Date, saved: string): TimezoneGroup[]`, где
  `TimezoneGroup = { label: string; options: { value: string; label: string }[] }`; `Select` принимает группы
  (`<optgroup>`), обычный список — как раньше.

Пункты:
1. **Часовой пояс — выпадающий список** (`Select`, вместо поля с подсказками), как в системных настройках:
   - группа «Россия» первой: Калининград, Москва, Самара, Екатеринбург, Омск, Новосибирск, Красноярск, Иркутск,
     Якутск, Владивосток, Магадан, Камчатка (`Europe/Kaliningrad` … `Asia/Kamchatka`) — подпись
     `(UTC+03:00) Москва`;
   - остальные — группами по части пояса до «/» по-русски (Европа, Азия, Америка, Африка, Австралия, Тихий океан,
     Атлантика, Индийский океан, Антарктида, Арктика, Другие), внутри — по смещению, затем по подписи;
     подпись `(UTC+01:00) Центральная Европа, стандартное время — Europe/Berlin`: смещение —
     `Intl.DateTimeFormat(…, { timeZoneName: 'longOffset' })` («GMT+01:00» → «UTC+01:00», «GMT» → «UTC+00:00»),
     название — `timeZoneName: 'long'` в `ru-RU`;
   - сохранённый пояс, которого нет в списке, — отдельной первой группой «Сейчас выбран» с подписью из его имени;
   - движок без `Intl.supportedValuesOf` — прежнее поле ввода (как сейчас).
   Vitest с фиксированной датой: у `Europe/Moscow` подпись с «(UTC+03:00) Москва», группа «Россия» первая, внутри
   групп порядок по смещению, неизвестный сохранённый пояс сохранён.
2. **Гарантия по умолчанию — выпадающий список**: пустой пункт «Не задана» и значения справочника гарантий без
   архивных; значение, которого в справочнике нет, — пунктом «{значение} (нет в справочнике)». Vitest страницы.
   «Мастер по умолчанию» не трогать — он уходит в план 5.8.
3. **Строки статусов, точек и справочников** (`CatalogRows`): одна сетка с постоянными колонками для всех строк —
   перетаскивание | название (переносится) | число заказов (вправо, постоянной ширины) | колонки раздела (у статусов:
   цвет, вид) | действия; строка заголовков колонок («Название», «Заказов», «Цвет», «Вид») вместо подписи «Вид» над
   каждым списком; пояснение видов — подсказкой `HelpHint` в заголовке «Вид» (текст на все четыре вида), а не текстом
   под каждым списком. Рядом со списком вида — иконка вида: Диагностика `stethoscope`, Открыт `wrench`, Готов
   `package-check`, Выдан `handshake`. «В архив» — кнопка с иконкой `archive` и текстом (на xs — только иконка с
   подписью для чтения с экрана и всплывающей подсказкой). Форма нового статуса — в тех же колонках. На xs строка
   может переноситься в две, но колонки внутри строк совпадают. Тесты: e2e — у всех строк статусов левый край кнопки
   цвета и списка вида совпадает (±1px) на md и xl, масштабах 1 и 1,25; обход экранов — статусы, точки, справочники
   на всех ширинах без переполнения; vitest `CatalogRows` — заголовки колонок.

### Task 4: Отчёт импорта — группы без заказов, пояснения, штрихкоды

**Files:** `crates/mw-legacy/src/view.rs` (+ тест рядом), контракт `crates/mw-api/{openapi.json,bindings/}`,
`apps/ui/src/lib/import/{ReportView.svelte,report.ts}` (+ тесты), `apps/ui/src/lib/i18n/ru.ts`, e2e импорта
(`apps/ui/e2e/import.spec.ts` или соседний).

**Interfaces:**
- Produces (API): `ReportEntry { source: String, key: String, field: String, value: String, message: String }`
  (`Serialize`, `TS`, `ToSchema`) и поле `ReportGroup.entries: Vec<ReportEntry>` — первые `REPORT_GROUP_ENTRIES = 200`
  предупреждений группы по порядку; `count` — по-прежнему все.
- Consumes: `HelpHint` (Task 2).

Пункты:
1. **Сервер:** `entries` у каждой группы, не больше 200. Тест: группа из 250 предупреждений → 200 записей, `count` 250;
   порядок как в отчёте. Контракт перегенерирован.
2. **Каждая группа раскрывается.** С номерами заказов — как сейчас (номера, «Показать все»); без заказов — список
   записей (поле или ключ, значение, пояснение), при обрезке — «Показаны первые 200 из N; полный список — в
   «Сохранить отчёт»». Группа без записей и без заказов не бывает; если бывает — строка без стрелки, как сейчас.
3. **Пояснения к каждой группе.** У заголовка группы — `HelpHint` с пояснением по её коду: что было в MyWork 2, что
   сделал перенос, что делать человеку (или «ничего делать не нужно»). Тексты — `ru.importReport.explain`, тип
   `Record<WarningCode, string[]>`, чтобы новый код без пояснения не прошёл проверку типов (все 42 кода из
   `crates/mw-legacy/src/report.rs`). Пояснение «Одинаковый штрихкод у нескольких заказов»: в MyWork 2 старые заказы
   получили штрихкод генератором, который из-за ошибки давал всего около 9 тысяч разных кодов, а новые — код из даты и
   времени до секунды и последней цифры года (два заказа в одну секунду совпадают); перенос оставил коды как были;
   сканер на таком коде покажет выбор заказа; новые заказы MyWork 3 получают свои неповторяющиеся коды.
4. **Переход к заказу.** e2e (Chromium и WebKit, синтетическая фикстура): группа без заказов раскрывается и показывает
   записи; нажатие на номер в группе с заказами открывает этот заказ (в панели виден его номер); значок пояснения
   открывает текст.

## Не делаем здесь (решения)

- Мастера — учётные записи, роли с правами галочками, «Мастер по умолчанию», пустой справочник мастеров после
  импорта, комментарии мастера — план 5.8.
- Карточка заказа (выезжающая панель и полный режим) — план 5.9: сначала разбор и варианты на выбор автора.
- Стрелку у всех полей с подсказками (`Combobox`) не добавляем: выпадающими списками становятся только поля, о которых
  сказал автор (часовой пояс, гарантия); поля приёма остаются полями с подсказками.
- Новые штрихкоды для заказов с повтором не выдаём: на выданных устройствах могут быть старые наклейки (гарантийный
  возврат); сканер и так предлагает выбор заказа.
