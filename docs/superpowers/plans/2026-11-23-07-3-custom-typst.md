# План 7.3 «Свой Typst-код» — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Цель:** опытный пользователь добавляет в шаблон блок «Typst-код» или превращает в него почти любой блок, правит код в редакторе с номерами строк и видит ошибки со строкой и знаком. Свой код строится в отдельном процессе-рендерере, который убивается через 5 секунд: бесконечный цикл не вешает сервер. Заодно закрыты заметки «План 7.3»: бюджет времени пачки, битый файл логотипа, двойное чтение шрифтов, число отправленных в уведомлении пачки, `blob:` логотипа.

**Архитектура:**
- **Модель.** Новый блок `BlockBody::TypstCode { code }` (`"type": "typst_code"`), допустим и в колонках.
- **Генератор.** Код блока — отдельный виртуальный исходник `/code-<путь>-<экземпляр>.typ`. Он начинается двумя строками заголовка: `#import "/mw.typ": *` и `#let copy = "…"`. Основной файл вставляет его через `include`. `/mw.typ` — те же помощники, что в начале каждого документа (`data`, `v`, `v1`, `one-line`, …).
- **Ошибки.** Ошибка Typst с местом в таком файле становится `CodeDiagnostic`: путь блока, строка и знак в коде пользователя.
- **Задание рендера.** `mw_docs::Job` — это шаблон, параметры, данные одного или нескольких документов, вывод (PDF или PNG) и пределы. Одну и ту же `run_job` выполняет:
  - сам сервер — для шаблонов без своего кода, как раньше;
  - процесс-рендерер — для шаблонов со своим кодом.
- **Процесс-рендерер.** Это та же программа (`mw-server` или программа для компьютера), запущенная с аргументом `--mw-render-worker`. Обмен идёт кадрами по stdin/stdout. `RenderPool` держит до двух готовых процессов. Процесс, который строит документ дольше 5 с или задание дольше бюджета, убивается; следующее задание запускает новый процесс.
- **Печать и превью.** Печать сохранённого шаблона, чей код не построился, идёт стандартным шаблоном с `tracing::warn!`. Превью несохранённого шаблона показывает ошибки.

**Tech Stack:** Rust (Typst 0.15.1, `std::process`, `serde_json`), Axum 0.8 + utoipa + ts-rs, SvelteKit 3 + Svelte 5, Tauri 2.

**Spec:**
- `docs/superpowers/specs/2026-11-11-mywork3-crossplatform-design.md`, §5.1 («опытный пользователь может переключить блок в режим «свой Typst-код»»; «Остаётся плану 7.3: свой Typst-код с пределом времени компиляции (отдельный процесс рендера)»);
- спека интерфейса `docs/superpowers/specs/2026-11-15-ui-design-system-design.md`, раздел 7 (редактор шаблонов);

## Решения плана

1. **Процесс-рендерер — только для шаблонов со своим кодом.**
   - Стандартный генератор не пишет бесконечных циклов: единственный `while` в `one-line` — это деление пополам. Поэтому шаблон без блоков `TypstCode` строится в процессе сервера, как раньше, без расходов на обмен.
   - Шаблон с кодом (`Template::has_code()`) строится только в процессе-рендерере.
   - В процессе сервера шаблон с кодом строится только в тестах (`Core::with_code_in_process`).
   - Ядро без пула отвечает 503: «Документы со своим Typst-кодом сейчас не строятся».
2. **Пределы времени:**
   - **5 с** на компиляцию одного документа. Отсчёт — от отправки задания или от готовности предыдущего документа пачки.
   - **25 с** — бюджет всего задания (`RENDER_BUDGET`), меньше 30 с `REQUEST_TIMEOUT`.
     - Процесс-рендерер, вышедший за бюджет на 1 с, убивается.
     - Внутри `run_job` бюджет проверяется после каждого документа. Этим закрыта заметка о пачке под 30 с, и для пачек без своего кода тоже.
   - **60 с** на запуск процесса: шрифты системы на медленном Windows. Запуск не входит ни в 5 с, ни в 25 с. Ещё не готовый процесс по истечении предела убивается.
   - Числа — константы `mw-core` (`CODE_DOCUMENT_LIMIT`, `WORKER_STARTUP_LIMIT`, `RENDER_BUDGET`). Тесты пула передают свои, короткие.
3. **Протокол.**
   - Кадр: `u32` длины (little-endian) и байты; кадр длиннее 256 МиБ — ошибка протокола.
   - Сообщение: один кадр JSON и объявленные в нём двоичные кадры (логотип, PDF, страницы PNG).
   - Порядок обмена:
     1. Родитель шлёт `Hello { fonts }`, рендерер отвечает `Ready`, когда собрал книгу шрифтов.
     2. На каждое задание `Run` рендерер шлёт `Compiled { index }` после каждого документа, затем `Done` (с байтами) или `Failed` (с ошибкой).
   - Рендерер пишет в stdout только кадры и не включает журнал.
   - Рендерер выходит:
     - по концу stdin (родитель закрылся) — с кодом 0;
     - при битом кадре — с кодом 2;
     - сам, если одно задание идёт дольше своего срока плюс 5 с, — с кодом 3. Так рендерер, у которого умер родитель, не крутит цикл часами.
   - Окна у процесса нет: на Windows флаг `CREATE_NO_WINDOW`. stderr наследуется.
4. **Песочница.**
   - `World` отдаёт только виртуальные файлы: `/main.typ`, `/mw.typ`, `/code-*.typ`, `data.json`, `logo.png`, `barcode.svg`.
   - Пакетов нет, `datetime.today()` — ошибка, на диск рендерер не пишет.
   - Память не ограничена: процесс, которому её не хватило, падает. Сервер отвечает ошибкой «прервалось», следующий документ запускает новый процесс.
5. **Что видит свой код:**
   - `data` (`values`, `blank`, `logo`, `barcode`) и помощники `v`, `v1`, `one-line`, `raw-value`, `filled`, `fill-line`, `short-line`, `vspace` (вертикальный отступ: `v` занят полем);
   - `copy` — `"single"`, `"service"` или `"client"`;
   - `image("logo.png")`, когда `data.logo`. Логотип передаётся документу, если в шаблоне есть блок `Logo` **или** блок кода.

   Штрихкод — только блоком «Штрихкод»: его модуль считается в точках принтера по блокам штрихкода. Поэтому блок штрихкода и колонки со штрихкодом в код не превращаются.
6. **Ошибки своего кода:**
   - `CodeDiagnostic { place: Option<CodePlace>, message, hints }`, где `CodePlace { block: Vec<usize>, line: u32, column: u32 }`:
     - строка считается с 1 в коде пользователя, без двух строк заголовка;
     - знак — с 1 в символах Unicode, как у `Lines::byte_to_column` в Typst.
   - **Как найти место:** место самой ошибки, если оно в файле кода. Иначе — первая точка `trace` в файле кода: ошибка внутри помощника указывает на вызов из кода.
   - **Одна ошибка на место:** одна и та же (место, текст) из двух экземпляров даётся один раз, не больше 20 штук.
   - **Шаблон с блоками кода:** каждая ошибка компиляции становится `CodeDiagnostic` (без места — `place: None`), и рендер отвечает `DocsError::Code`. В шаблоне без кода всё как раньше (`DocsError::Compile` — внутренняя ошибка).
   - **Тексты:** сообщения Typst идут как есть (по-английски); русское — то, что вокруг: «строка 2, знак 5».
   - **Ответ API:** 422 `validation` с сообщением «Ошибка в своём Typst-коде».
     - `fields` — по одному на блок: `blocks.N.code` или `blocks.N.columns.C.J.code` с кодом `typst_error`; ошибки без места — `template`/`typst_error`.
     - Новое поле `ErrorBody.diagnostics` — список ошибок; у остальных ответов оно пустое.
   - **Остальные отказы:**

     | Случай | Поле / код | HTTP |
     | --- | --- | --- |
     | Документ дольше 5 с | `template`/`code_timeout` | 422 |
     | Процесс упал | `template`/`code_crashed` | 422 |
     | Задание дольше бюджета | `documents`/`too_slow` | 422 |
     | Рендерер не запустился | `CoreError::Unavailable` | 503, `tracing::error!` |
7. **Печать сохранённого шаблона не ломается из-за своего кода.**
   - Когда `export_document` без `draft` или `export_documents` получает отказ своего кода, документ строится стандартным шаблоном в процессе сервера с `tracing::warn!` (вид документа и ошибка). Отказы своего кода: ошибки, 5 с, падение, рендерер недоступен или не настроен.
   - Это продолжение правила плана 7.1: модель, которую не прочитать, печатается стандартной. Приём заказа из-за шаблона не ломается.
   - Предел страниц, пикселей и `too_slow` — не отказ кода: они отвечают ошибкой, как раньше.
   - Превью несохранённого шаблона (`draft`) показывает ошибки, без запасного пути.
8. **Превращение блока в код** — `mw_docs::block_code`. Это Typst-код, который печатает то же, что блок; проверяется совпадением PNG на стандартных шаблонах.
   - Выражение блока строится для трёх экземпляров (`single`, `service`, `client`):
     - совпали все три — код `#{` выражение `}`;
     - иначе — `#if copy == "service" {…} else if copy == "client" {…} else {…}`.
   - `copies` блока сохраняется. В истории это один шаг, его можно отменить.
   - Недоступно для штрихкода, колонок со штрихкодом, блока кода и меток калибровки.
9. **Пределы модели:**
   - код блока — до 20 000 знаков (`MAX_CODE_CHARS`);
   - весь код шаблона — до 50 000 знаков (`MAX_TEMPLATE_CODE_CHARS`), отдельно от бюджета текста 20 000;
   - пустой код допустим и ничего не печатает;
   - `TEMPLATE_FILE_VERSION` становится 3.
10. **Редактор кода** — свой компонент `CodeEditor` на `<textarea>`, без новой зависимости:
    - моноширинный шрифт `--font-mono`, без переноса строк, без проверки орфографии;
    - полоса номеров строк, в ней отмечены строки с ошибками; список ошибок — под полем;
    - Tab работает как обычно и переводит фокус: клавиатурной ловушки нет;
    - подсветки синтаксиса нет: это решение до первой просьбы.
11. **Поле в своём коде.** `DocumentField` получает `key` (`order.number`). «Вставить поле» у блока кода вставляет `#v("order.number")`.
12. **Кто запускает рендерер.**
    - `Config.render_worker: Option<PathBuf>`:
      - сервер (`cli`) и программа для компьютера (`launch`) кладут туда `std::env::current_exe()`;
      - тесты — `None`.
    - `Server::start_with_db` при `Some` создаёт пул и в фоне запускает один процесс (`warm`).
    - Аргумент `--mw-render-worker` проверяется первым делом в `main` обеих программ, до `clap`, `tokio`, блокировки папки данных и Tauri.
13. **Заметку о `plain_text`** (`<a:b c>`, `<mailto:xy>`) план не трогает: находок импорта нет. Она переезжает в «Общее» README.

## Review Focus

1. **Бесконечный или очень долгий цикл в своём коде** (`for` по `range(100000)` внутри такого же `for`).
   - Ожидание: превью отвечает примерно через 5 с ошибкой «дольше 5 секунд»; сервер всё это время отвечает на другие запросы; следующее превью строится.
   - Тест — в задаче 6 (пул) и задаче 7 (через HTTP).
2. **Ошибка своего кода указывает не на ту строку:**
   - сдвиг на строки заголовка;
   - два экземпляра «2 на лист» дают одну ошибку, а не две;
   - ошибка внутри помощника (`v(5)`) указывает на вызов;
   - блок в колонке назван полным путём.

   Тест — в задаче 2.
3. **Чужой `.mwtemplate` с кодом:** код пытается прочитать файл системы, подключить пакет или взять сегодняшнюю дату. Ожидание: ошибка в превью, никаких данных с диска. Тест — в задаче 2.
4. **Сохранённый шаблон со своим кодом не строится при печати** (ошибка, 5 с на медленном ПК, рендерер не запустился). Ожидание: акт при приёме печатается стандартным шаблоном, запись в журнал. Тест — в задаче 7.
5. **Запуск рендерера на медленном Windows с большой папкой шрифтов** и смерть родителя.
   - Ожидание:
     - запуск не съедает 5 с компиляции (свой предел 60 с);
     - рендерер выходит сам, когда закрыт stdin;
     - если рендерер завис в цикле, он выходит сам, когда задание переросло срок.
   - Тест — в задачах 5 и 6.

**Interfaces:**
- Produces:

  - Типы ошибок кода, оба с `Debug, Clone, PartialEq, Eq, Serialize, Deserialize, TS, ToSchema`:
    ```rust
    pub struct CodePlace { pub block: Vec<usize>, pub line: u32, pub column: u32 }
    pub struct CodeDiagnostic { pub place: Option<CodePlace>, pub message: String, pub hints: Vec<String> }
    ```
    В `CodeDiagnostic` поле `place` с `#[schema(required = true)]`, как `Option` у `ErrorBody`.
  - `impl Template { pub fn has_code(&self) -> bool }` — заглядывает и в колонки.

  - Ошибки проверки:
    - код блока длиннее предела → `blocks.N.code` (в колонке `blocks.N.columns.C.J.code`) / `too_long`;
    - весь код длиннее предела → `blocks` / `code_budget`.
  - Тексты `FieldError::message_ru` — для всего плана сразу:

    | Код | Текст |
    | --- | --- |
    | `code_budget` | «Весь Typst-код шаблона — не больше 50 000 знаков» |
    | `typst_error` | «Ошибка в Typst-коде» |
    | `code_timeout` | «Свой Typst-код строится дольше 5 секунд — проверьте циклы» |
    | `code_crashed` | «Построение документа прервалось — возможно, своему Typst-коду не хватило памяти» |
    | `too_slow` | «Документы строятся дольше 25 секунд — напечатайте пачку частями» |
    | `code_unavailable` | «Этот блок нельзя превратить в Typst-код» |
  - Интерфейс:
