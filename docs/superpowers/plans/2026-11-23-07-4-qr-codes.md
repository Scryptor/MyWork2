# План 7.4 «QR-коды на документах» — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Цель:** на актах и наклейках печатается QR-код со ссылкой: на Telegram-канал фирмы, её карточку на Google или Яндекс Картах или любую свою ссылку (предложение клиента от 2026-11-23). Ссылки фирмы вводятся один раз в «Документы и реквизиты», в шаблон ставится блок «QR-код». Заодно закрыты остатки плана 7.3.

**Архитектура:**
- **Модель.** Новый блок `BlockBody::Qr { link, size_mm, caption, align }` (`"type": "qr"`), допустим и в колонках. `link` — текст шаблона с подстановками, как значение строки «Поля».
- **Ссылки фирмы.** Три настройки (`firm_telegram`, `firm_google_maps`, `firm_yandex_maps`) и три поля подстановки (`{фирма.телеграм}`, `{фирма.гугл_карты}`, `{фирма.яндекс_карты}`). Заготовка в блоке — это ссылка из одной такой подстановки.
- **Код строит сервер**, как штрихкод: `mw-docs` подставляет значения в ссылку, кодирует её крейтом `qrcode` и кладёт SVG в виртуальный файл `qr-<имя>.svg`. Разметка Typst знает только имя файла; ссылка и данные заказа в разметку не попадают. Список построенных имён — `data.qr` в `data.json`.
- **Свой Typst-код** получает файлы ссылок фирмы и помощник `qr-image(name, width)` из `/mw.typ`; блок «QR-код» с заготовкой превращается в код, со своей ссылкой — нет (как штрихкод).

**Tech Stack:** Rust (Typst 0.15.1, `qrcode` 0.15, `rqrr` 0.11 только в тестах), Axum 0.8 + utoipa + ts-rs, SvelteKit 3 + Svelte 5.

**Spec:**
- `docs/superpowers/specs/2026-11-11-mywork3-crossplatform-design.md`, §5.1 (блоки содержимого: «…штрихкод, QR-код…»; таблица технологий: «`qrcode` → SVG в Typst»);
- спека интерфейса `docs/superpowers/specs/2026-11-15-ui-design-system-design.md`, раздел 7 (редактор шаблонов);
- заметки «План 7.4» в `docs/superpowers/plans/README.md`; остатки плана 7.3 — там же и в разделе «Решения» ниже.

## Решения

1. **Ссылка — текст шаблона с подстановками.** Сервер подставляет значения (`DocumentData::values`) и обрезает пробелы по краям. QR-кода нет, и блок не занимает места, если ссылка пуста или хоть одна подстановка в ней пуста (полкода хуже, чем ничего; в пустом акте поля заказа пусты — QR-кода с ними нет). Ссылка, которая не помещается в QR-код, тоже не печатается.
2. **Ссылки фирмы — настройки** `firm_telegram`, `firm_google_maps`, `firm_yandex_maps` (пусто или `http://`/`https://` без пробелов, до 500 знаков; ошибки `not_a_link`, `too_long`) и поля подстановки:

   | ключ | в тексте | для людей | образец |
   |---|---|---|---|
   | `firm.telegram` | `фирма.телеграм` | Telegram фирмы | `https://t.me/example_service` |
   | `firm.google_maps` | `фирма.гугл_карты` | Фирма на Google Картах | `https://maps.google.com/?q=example` |
   | `firm.yandex_maps` | `фирма.яндекс_карты` | Фирма на Яндекс Картах | `https://yandex.ru/maps/?text=example` |

   Они стоят в меню «Вставить поле» сразу после `firm.legal`, их можно печатать и текстом.
3. **Символ.** `qrcode` 0.15 с `default-features = false, features = ["std"]`; SVG строим сами (как `barcode.rs`): `viewBox="0 0 n n"`, один `<path>` из горизонтальных отрезков тёмных модулей, без тихой зоны. Уровень коррекции — M. Модуль не подгоняется под точки принтера: QR-коды читаются по центрам модулей.
4. **Размер.** `size_mm` — сторона квадрата модулей, 10–100 мм; в колонке уже стороны код сжимается до ширины колонки (сторону считает генератор в мм). Подпись (`caption`, текст с подстановками, до 200 знаков, входит в бюджет текста шаблона) печатается под кодом по центру, шрифтом 0,85 от текущего.
5. **Имена файлов.** Ссылка из ровно одной подстановки ссылки фирмы (пробелы по краям не в счёт) — имя файла это ключ поля: `qr-firm.telegram.svg`. Иначе — `block-<путь через «-»>`: `qr-block-3.svg`, `qr-block-2-0-1.svg`. Один файл на имя: два блока с одной заготовкой показывают один файл в своих размерах.
6. **Свой код.** Шаблон со своим кодом получает файлы всех непустых ссылок фирмы. В помощниках (`PRELUDE`, а значит и `/mw.typ`): `qr-image(name, width)` — картинка `qr-<name>.svg` шириной `width` или ничего, если такого файла нет. `block_code` переводит блок «QR-код» с заготовкой (решение 5) — его выражение и так читает только файл ссылки фирмы; блок со своей ссылкой не переводится, как штрихкод.
7. **Стандартные шаблоны не меняются:** QR-код появляется только там, куда его поставили.
8. **Остатки плана 7.3** (задача 1): флаг замены процесса снимает страж при любом выходе из потока, даже при панике; замена не пропускается, когда среди простаивающих только закрывшиеся процессы; ошибка PDF/PNG в `CoreError::Internal` — без текста Typst (в нём может быть значение из документа); «Вставить поле» не считает скобку в тексте разметки (`Телефон (рабочий)`) началом кода.

## Review Focus

1. **Ссылка не латиницей** (`https://t.me/сервис`, путь Яндекс Карт с кириллицей) кодируется байтами UTF-8 и читается обратно той же строкой — тест в задаче 3.
2. **QR-код в узкой колонке** (наклейка 40×30 или три колонки), где `size_mm` шире колонки, сжимается до ширины колонки и читается — тест в задаче 3.
3. **Фирма не заполнила ссылку:** блок не печатается и не оставляет пустого места, ошибки нет — лист такой же, как без блока; тест в задаче 3.
4. **Пустой акт** с QR-кодом, в ссылке которого `{заказ.номер}`: кода нет (не полссылки) — тест в задаче 3.
5. **Ссылка без схемы** в настройках (`t.me/servis`, `@servis`): ошибка поля с понятным текстом, а не QR-код с текстом вместо ссылки — тест в задаче 2 (ядро) и задаче 5 (текст в интерфейсе).
