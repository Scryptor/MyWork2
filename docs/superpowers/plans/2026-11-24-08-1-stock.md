# План 8.1 «Склад» — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Цель:** склад запчастей — позиции с остатком, ценой, порогом «Докупить» и фото; списание запчастей в заказ и возврат на склад; себестоимость заказа = «Расходы» + запчасти; склад MyWork 2 переносится при импорте и кнопкой — в уже импортированные базы. Первой задачей чинятся два нестабильных сквозных теста WebKit.

**Архитектура:**
- **Данные.** `stock_items` — позиция (мягкое удаление, `version`, `search_text`, `name_key`); `order_parts` — строка списания со снимком наименования и цены; `attachments.stock_item_id` — фото позиции; `audit_log.stock_item_id` — журнал позиции. Вид справочника `PartType` живёт в коде (`DictionaryKind`), его стартовые значения — миграция данных.
- **Ядро.** Модуль `mw-core/src/stock/`: позиции, фото, запчасти заказа. Списание и возврат — одна транзакция `begin_write()` с условным `UPDATE … WHERE quantity >= n`: остаток не уходит ниже нуля. Версия заказа при списании не меняется, версия позиции — меняется.
- **Импорт.** Чистый конвертер `mw-legacy/src/convert/stock.rs` принимает `LegacyTable` — и из старой базы, и восстановленные из `legacy_rows` прошлого импорта. Пакет импорта получает `ImportBundle.stock`; перенос в уже импортированную базу — `Core::import_stock` одной транзакцией.
- **Интерфейс.** Раздел «Склад» (`/stock`) по образцу «Клиентов» (`createPagedList`, `createEntityEditor`, вид в адресе); фото — `OrderPhotos` с `createStockMedia`; блок «Запчасти» в панели и полной карточке заказа; новый `#lib/ui/QuantityInput.svelte`.

**Tech Stack:** Rust (SeaORM + SeaQuery, Axum 0.8 + utoipa + ts-rs), SvelteKit 3 + Svelte 5, Playwright (Chromium, WebKit). Новых зависимостей нет.

**Spec:**
- `docs/superpowers/specs/2026-11-11-mywork3-crossplatform-design.md`: §5 п. 5 «Склад» и п. 2 (запчасти со склада в карточке, расчёт), §6 (`Stock → stock_items (+ фото …)`, `StockMap → order_parts (clientId = id заказа)`), §7 (схема);
- `docs/superpowers/specs/2026-11-15-ui-design-system-design.md`: «Склад (план 8)» — список и панель, как у заказов (вкладка «Карта» — план 8.4);
- `docs/superpowers/plans/README.md`: заметки «План 8.1», идеи «Склад, цены и расчёты».

## Global Constraints

- Код и идентификаторы — на английском; тексты для людей и документация — на русском. Комментарии — на языке файла (в `mw-core`, `mw-db`, `mw-legacy` — русский, в `apps/ui` — английский).
- Слои: `mw-domain` — без ввода-вывода; к БД — только через `mw-db` и `mw-core`; права проверяет `mw-core`; любая запись в БД — только через `Core::begin_write()`.
- Сначала тест, потом код. Каждый тест с БД идёт по `all_backends()`.
- Перед коммитом зелёным должно быть:
  - Rust: `cargo fmt --all --check && cargo clippy --workspace --all-targets -- -D warnings && cargo check --workspace && cargo test --workspace`;
  - интерфейс (задачи, которые его трогают): `cd apps/ui && npm run verify && npm run test:e2e`.

  `cargo check` собирает без dev-зависимостей: рабочий код не пользуется тем, что открыто только для тестов (`Actor::for_tests`, `Core::db()`).
- Деньги — только `Money` (копейки), время — только `Core::now()`, поиск без учёта регистра — только `mw_domain::search`.
- Выпущенные миграции не меняются; стартовые данные (значения справочника, права готовых ролей) — только новой миграцией данных с замороженными литералами.
- Типы API — типы `mw-core`/`mw-domain` с `Serialize`/`Deserialize`, `ts_rs::TS` и `utoipa::ToSchema`. Входные типы — с `deny_unknown_fields`; в правках «не передано» и `null` — через `patch::present`/`patch::nullable`. `#[ts(export)]` не ставить.
- `crates/mw-api/openapi.json` и `crates/mw-api/bindings/` генерируются: `MW_UPDATE_CONTRACT=1 cargo test -p mw-api --test contract -- --test-threads=1`, затем `cargo test -p mw-api --test contract`; коммит — вместе с кодом.
- Правка без изменений не создаёт версию и запись в журнал; устаревшая `version` в такой правке не даёт 409.
- `SEARCH_INDEX_VERSION` 4 → 5 (задача 3): в индекс входят позиции склада.
- Вложения: файлы — только через `mw-core::attachments`, пути — через `store::resolve`; загрузка — телом `application/octet-stream`.
- Импорт MyWork 2: всё неразобранное — в отчёт и в `legacy_rows` в исходном виде. Новая форма значения — сначала строка в `mw_legacy::fixture` с ожидаемым результатом в тесте, потом код разбора. Фикстуры только синтетические; `real_db` печатает только числа.
- Правила интерфейса (`AGENTS.md`): ширины — только `display` и `:global([data-width=…])`; цвета и размеры — только из `tokens.css`; Svelte 5 на рунах, обработчики — пропсы `on…`; импорты `#lib/...` с явными расширениями, типы API — `import type` из `$api/...`; компоненты — из `#lib/ui/...` (новые — туда же с разделом на `/design`); тексты — в `#lib/i18n/ru.ts`; иконки — `@lucide/svelte` по одной; `fetch` — только в `src/lib/api/client.ts`; деньги — `#lib/format/money.js` и `MoneyInput`; даты — `#lib/format/date.js`; картинки — `attachmentUrl`; автосохранение — `createAutosave`; Ctrl/⌘+Enter в диалогах — `submitShortcut`.
- Сквозные тесты: Chromium и WebKit, запросы по ролям и подписям, настоящий `mw-server`, данные — через API с меткой `uniq()`; камера — только в Chromium.
- Субагенты: `cargo` и `rustc` — только внутри worktree с `CARGO_TARGET_DIR=/Users/ruf/dev/MyWork2/target`; ждать долгие команды через фоновый запуск и его уведомление, без циклов с `pgrep -f`; логи — в папке черновиков, не в `/tmp`.

## Решения

1. **Разбивка плана 8.** 8.1 «Склад» — этот план. 8.2 «Отчёты и экспорт» (ECharts, Excel через `rust_xlsxwriter`, экспорт заказов и клиентов, контакты CSV/vCard, оплата мастеру). 8.3 «Резервные копии» (`VACUUM INTO` + вложения, ручная копия, восстановление, N последних, настройки из `EveryDayBackup`/`backupPath`). 8.4 «Карта склада» (§5.5; сначала варианты дизайна для автора). Не в этом плане: карта, ячейки, места хранения, наклейки ячеек, отчёты, экспорт, поиск склада в Ctrl K, мобильные сценарии склада (план 10; список и панель на телефоне работают как у «Клиентов»).

2. **Позиция склада** — таблица `stock_items`:

   | столбец | тип | смысл |
   |---|---|---|
   | `id` | BIGINT PK, автоинкремент | номер позиции, в интерфейсе «Арт.»; у перенесённых — `Stock.id` |
   | `name` | TEXT NOT NULL '' | наименование, как ввёл человек; пусто — выводится |
   | `device_type`, `part_type`, `brand`, `model`, `color` | TEXT NOT NULL '' | поля позиции; справочники — подсказки, как в заказе |
   | `note` | TEXT NOT NULL '' | примечание |
   | `quantity` | BIGINT NOT NULL 0 | остаток, ≥ 0 |
   | `price` | BIGINT NOT NULL 0 | цена за штуку, копейки («сколько стоит вам») |
   | `restock_threshold` | BIGINT NOT NULL 0 | «Докупить при», 0 — не напоминать |
   | `search_text`, `name_key` | TEXT NOT NULL '' | индекс поиска; `normalize_search(display_name)` для сортировки |
   | `created_at`, `updated_at` | TIMESTAMP NOT NULL | |
   | `deleted_at` | TIMESTAMP NULL | мягкое удаление |
   | `version` | BIGINT NOT NULL 1 | одновременная правка, как у заказа |

   Индекс `idx_stock_items_name_key`. Проверки — в ядре (CHECK в схеме проект не использует): тексты ≤ 200 знаков, примечание ≤ 2000 (`too_long`); количество и порог 0…`MAX_STOCK_QUANTITY` = 1 000 000, цена 0…`MAX_STOCK_PRICE` = 10 000 000 ₽ (`out_of_range`); наименование и все пять полей пусты — `name` `required`.
   **Выводимое наименование** (`mw_domain::stock::display_name`): введённое (без пробелов по краям), иначе непустые «тип запчасти, тип устройства, бренд, модель, цвет» через пробел, иначе «Позиция №{id}». **«Докупить»** (`needs_restock`): `restock_threshold > 0 && quantity < restock_threshold`.

3. **Запчасть заказа** — таблица `order_parts`: `id` (PK), `order_id` (NOT NULL, FK `orders`), `stock_item_id` (NULL, FK `stock_items`; NULL — позиции не было уже в MyWork 2), `name` (снимок `display_name`), `price` (снимок цены, копейки), `quantity` (BIGINT), `added_by_id` (NULL, как `order_comments.author_id`), `added_by_name` (TEXT), `added_at`, `legacy` (BOOL NOT NULL false — перенесена из MyWork 2), `request_key` (TEXT NULL; уникальный индекс `(order_id, request_key)`, NULL у перенесённых). Индексы по `order_id` и `stock_item_id`.

4. **Списание** — `Core::add_order_part`: права `orders_edit` + `stock_view`. Заказ есть и не удалён (иначе `NotFound` / `id` `deleted`); позиция есть и не удалена (иначе `NotFound` / `stock_item_id` `deleted`); количество 1…1 000 000 (`quantity` `out_of_range`). В одной транзакции: `UPDATE stock_items SET quantity = quantity - n, version = version + 1, updated_at = now WHERE id = ? AND deleted_at IS NULL AND quantity >= n`; ноль строк — `quantity` `not_enough_stock` (или `deleted`, если позицию удалили). Затем строка `order_parts` со снимком и запись журнала `order.part_added` (`order_id`, `client_id`, `stock_item_id`; «Списано со склада: {имя} × {n} — {сумма}»). Повтор с тем же `request_key` и тем же содержимым — ответ без нового списания; с другим содержимым — `request_key` `duplicate`. **Версия заказа не меняется** (несохранённая правка карточки не получает 409); **версия позиции меняется** (открытая панель позиции не затрёт остаток устаревшим числом).

5. **Возврат** — `Core::return_order_part`: те же права; строка принадлежит заказу (иначе `NotFound`), заказ не удалён. Строка удаляется; позиция жива — остаток += n, версия + 1; позиции нет (удалена, или `stock_item_id` NULL) — только снятие строки. Журнал `order.part_returned` («Возвращено на склад: …» / «Снято с заказа, позиции на складе нет: …»). Повторный возврат той же строки — 404; интерфейс считает его выполненным и перечитывает список.

6. **Деньги заказа.** Тип `Order` не меняется. `OrderParts { parts, total }`, `total` = Σ `quantity × price` (через `checked_mul`; переполнение невозможно при пределах решения 2). Себестоимость = `extra_costs` + `total` — считает интерфейс (`orderCost`). «К оплате» не меняется. Удаление заказа (мягкое) запчасти на склад не возвращает (как MyWork 2); у удалённого заказа блок «Запчасти» только для чтения; подтверждение удаления заказа с запчастями говорит, что они на склад не вернутся.

7. **Удаление позиции** — мягкое (`stock_delete`): пропадает из списка, подбора и счёта «Докупить»; строки списания остаются со снимком (`item_exists = false`); восстановления удалённой позиции в 8.1 нет.

8. **Журнал.** `audit_log.stock_item_id` (+ индекс), поле во `NewAuditEntry`, `AuditEntry`, `AuditFilter`, `AuditListQuery`. Действия: `stock.created`, `stock.updated` (как `order.updated`: подписи полей «наименование», «тип устройства», «тип запчасти», «бренд», «модель», «цвет», «примечание», «количество», «цена», «докупить при»), `stock.deleted`, `attachment.added`/`attachment.deleted` с `stock_item_id`, `order.part_added`, `order.part_returned`, `order.costs_split`, `legacy.stock_imported`. `list_audit` без `audit_view` разрешён при заданном `stock_item_id` и праве `stock_view`.

9. **Права.** Список, позиция, история, фото (чтение), сводка — `stock_view`; добавление — `stock_create`; правка и фото (добавить, подпись, удалить) — `stock_edit`; удаление — `stock_delete`; списание и возврат — `orders_edit` + `stock_view`; список запчастей заказа — как сам заказ (без отдельного права). Готовые роли «Мастер» и «Приёмщик» получают `stock_view` (мастер списывает запчасти, приёмщик отвечает «есть ли на складе») — миграцией данных, только если права роли не менялись (совпадают с прежним литералом); литералы `MASTER_ROLE_PERMISSIONS` и `RECEPTIONIST_ROLE_PERMISSIONS` — с `stock_view`, права в порядке `Permission` (как `SEED_ADMIN_PERMISSIONS`).

10. **Справочник «Типы запчастей».** `DictionaryKind::PartType` (`"part_type"`, «Типы запчастей»), в `DEFAULT_DICTIONARY` после `Color`: «Дисплей», «Аккумулятор», «Разъём зарядки», «Шлейф», «Камера», «Динамик», «Микрофон», «Корпус», «Стекло», «Кнопка», «Плата». Счёт использования и «переименовать/объединить везде» — по `stock_items.part_type` (живые позиции). Переименование типов устройств, брендов и цветов склад не трогает: на складе это подсказки, не ссылки.

11. **Поиск.** `stock_search_text` = `index_text` из `display_name`, `name`, `part_type`, `device_type`, `brand`, `model`, `color`, `note`; слова запроса — `search_tokens` + `like_contains` (все слова); запрос из одного целого числа находит ещё позицию с таким номером. Переиндексация пересчитывает `search_text` и `name_key` позиций; `ReindexStats.stock_items`.

13. **Импорт `Stock`.** Строка → позиция: `id` → `id` (целое > 0; иначе строка не переносится, `stock_row_skipped`, остаётся в `legacy_rows`); `Naimenovanie` → `name` как есть, только без пробелов по краям (в MyWork 2 его всегда собирал код; верхний регистр сохраняется); `Kategoriya` → `device_type`; `Podkategoriya` → `part_type`; `Brand`, `Model`, `Colour`, `Primechanie` → `brand`, `model`, `color`, `note`; `CountOf` → `quantity` и `Napominanie` → `restock_threshold` через `parse_quantity` (неразобранное — 0 и `quantity_unparsed`); `Price` → `price` через `parse_money` (неразобранное — 0 и `money_unparsed`); `Photo`, `Photo2`, `Photo3` — фото (файлы уже копирует импорт в `attachments/stock/<id>/`; следы `Stock.Photo` получают цель `StockItem(id)`, вложения создаёт `mw_db::backfill::legacy_stock_photos`). `created_at` = `updated_at` = время импорта. След `Stock` → цель `StockItem(id)`.
    `parse_quantity`: после обрезки — цифры, допускаются хвосты «.0…» и «,0…» (`3`, `3.0`, `3,00`), ≤ 1 000 000; иначе `None`.

14. **Импорт `StockMap`.** Строка → запчасть: `clientId` — номер заказа (заказа в пакете нет — запчасть не создаётся, `stock_part_without_order`, след без цели); `ZIPId` — позиция (нет — `stock_item_id` NULL, снимок «Позиция №{ZIPId} (нет на складе)», `stock_part_orphan`); `name` — `display_name` позиции; `price` ← `priceOfZIP`, `quantity` ← `countOfZIP` (неразобранное — 0 и предупреждение); `legacy = true`, `added_by_name` = '', `added_at` = время импорта. Несколько строк одной пары — несколько запчастей. Остаток не меняется (StockMap — уже списанное). След `StockMap` → цель `Order(clientId)`, если заказ есть.
    **«Расходы» заказа:** Σ = сумма `quantity × price` его запчастей; `extra_costs = Zatrati − Σ`, если ≥ 0; иначе `Zatrati` остаётся, предупреждение `extra_costs_kept` (ключ — номер заказа, значение «затраты X, запчасти Y»).

15. **Списки склада.** `settings/Stock/TypeOvZIP.txt` — файл справочника `PartType` (строка `(PartType, "Stock/TypeOvZIP.txt")` в `DICTIONARY_FILES`: есть файл — его значения, нет — стандартные). После сборки справочников добавляются в конец, если их ещё нет (`normalize_search`): к `PartType` — значения `Podkategoriya` позиций; к `DeviceType`, `Brand`, `Color` — строки `settings/Stock/ustrojstvo.txt`, `brands.txt`, `DeviceColour.txt`.

16. **Отчёт импорта.** Новые коды (после `FileUnreadable`, уровень Warning): `quantity_unparsed` «Не разобрано количество», `stock_row_skipped` «Позиция склада не перенесена», `stock_part_orphan` «Запчасть заказа без позиции склада», `stock_part_without_order` «Списание со склада без заказа», `extra_costs_kept` «Расходы заказа оставлены как есть»; Info (перед `NextNumber`): `stock_imported` «Склад перенесён» (значение «позиций N, запчастей M»). `stock_preserved` больше не выдаётся, вариант остаётся для старых отчётов (его текст в интерфейсе — про кнопку переноса). Кодов 44 → 50. `ImportSummary.stock_items`, `order_parts` — с `#[serde(default)]`; `summary_text` — строка про склад.

17. **Перенос в уже импортированную базу.** Доступен (`LegacyStockState.available`), когда есть хотя бы один импорт, у последнего (наибольший `id`) есть следы `Stock`, а `stock_items` и `order_parts` пусты. Права — как у импорта (`settings_manage` + `users_manage`), не только с этого компьютера (папка MyWork 2 не нужна); во время идущего импорта — отказ `import_running`. Источник — следы последнего импорта: `Stock`, `StockMap`, `Stock.Photo`, `file` с ключами `settings/Stock/*.txt`, и `Catalog` заказов из `StockMap`. Расходы: правятся только у заказов, чьи текущие `extra_costs` равны разобранному `Zatrati` из следа `Catalog` (то, что записал импорт); изменённые после импорта не трогаются — `extra_costs_kept` с пояснением «расходы менялись после импорта». Правка — `UPDATE … SET extra_costs = to, version = version + 1 WHERE id = ? AND extra_costs = from` и журнал `order.costs_split` у заказа («Из расходов выделены запчасти со склада MyWork 2: было X, стало Y»).
