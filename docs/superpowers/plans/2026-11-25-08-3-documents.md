# План 8.3. Доводка документов

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** четыре пункта «Идей» о документах:
- свои ссылки для QR-кодов вместо трёх постоянных полей;
- готовый акт «Как в MyWork 2»: альбомный A4, два экземпляра рядом;
- справка по Typst-коду в редакторе шаблонов;
- вставка в Typst-код бейджами.

**Architecture:**
- Ссылки становятся списком `firm_links` в настройках (`FirmLink { id, name, url, enabled }`). Миграция данных переносит в него три старых ключа.
- В документах ссылка — подстановка `{ссылка.<id>}`, значение лежит в `data.values["link.<id>"]`. Старые `{фирма.телеграм}`, `v("firm.telegram")` и `qr-image("firm.telegram", …)` остаются псевдонимами, поэтому сохранённые шаблоны печатаются как раньше.
- Модель шаблона (версия 5) получает:
  - раскладку `two_across`;
  - у текста — рамку и нумерованный список;
  - у таблицы — сетку.
- Готовые варианты строит `mw-docs` (`presets(kind)`), API отдаёт их рядом со стандартным шаблоном. Редактор применяет вариант одним шагом с отменой, как «Сбросить к стандартному».
- Справка и бейджи — интерфейс. Их примеры кода лежат в одном JSON. Rust-тест компилирует каждый пример, поэтому справка не может разойтись с тем, что умеет рендерер.

**Tech Stack:** Rust (mw-domain, mw-db/SeaORM, mw-core, mw-api/Axum + utoipa + ts-rs, mw-docs/Typst 0.15.1), SvelteKit 3 + Svelte 5 (руны), bits-ui 2.21, Playwright.

## Решения плана

1. **Ссылка — `FirmLink { id, name, url, enabled }`**, список `AppSettings.firm_links`, ключ `firm_links` в таблице `settings` (JSON, как `issue_required`).
   - Встроенные ссылки, по порядку: `yandex_maps` «Яндекс Карты», `2gis` «2ГИС», `telegram` «Telegram», `max` «MAX». Все включены, адреса пусты.
   - Встроенную ссылку можно выключить и переименовать, но не удалить. Свою можно удалить.
   - `id` — `[a-z0-9_]`, от 1 до 40 знаков. Новой ссылке его даёт интерфейс: `link_` + `Date.now().toString(36)`. Сервер только проверяет формат и уникальность. От имени `id` не зависит, так что переименование и перестановка шаблонам не мешают.
   - Ограничения:
     - не больше 20 ссылок;
     - имя — от 1 до 60 знаков после обрезки пробелов, без учёта регистра не повторяется (`mw_domain::search`);
     - адрес — пусто или http(s) до 500 знаков, пробелы по краям обрезаются (как у нынешних ссылок).
   - Правка списка заменяет его целиком. В журнал идёт одна запись «ссылки для QR-кодов»; правка без изменений записи не даёт.
2. **Перенос.** Миграция данных `m20261125_000001_firm_links`:
   - если хоть один из ключей `firm_telegram`, `firm_google_maps`, `firm_yandex_maps` не пуст и ключа `firm_links` ещё нет, записывает список: четыре встроенные ссылки, где у `yandex_maps` и `telegram` старые адреса, а в конце, если старый адрес Google Карт не пуст, ещё `google_maps` «Google Карты»;
   - три старых ключа удаляет в любом случае.
   - Поля `firm_telegram`, `firm_google_maps`, `firm_yandex_maps` уходят из `AppSettings` и `SettingsPatch` (предрелиз, совместимость API не нужна).
3. **Псевдонимы.** Старые шаблоны должны печататься как раньше:
   - `{фирма.телеграм}`, `{фирма.гугл_карты}`, `{фирма.яндекс_карты}` читаются как `{ссылка.telegram}`, `{ссылка.google_maps}`, `{ссылка.yandex_maps}`;
   - значения `firm.telegram`, `firm.google_maps`, `firm.yandex_maps` в `data.values` остаются (для `v(...)` в своём коде);
   - `qr-image` переводит старые имена `firm.*` в `link.*`.
   - Три статических поля уходят из реестра `fields()` (38 → 35 полей). Ссылки попадают в список полей для «Вставить поле» из настроек: «Ссылка: <имя>».
4. **Выключенная ссылка и ссылка, которой нет в списке, — пустое значение.** QR-блок с ней ничего не печатает и места не занимает. `{ссылка.<id>}` с правильным по форме `id` всегда считается подстановкой ссылки, даже если такой ссылки нет: печатается пусто, а не `{ссылка.x}` как текст.
5. **Акт MyWork 2 — готовый вариант на выбор, стандартный не меняется.** Стандартные акты остаются «два на A4» плана 6. В редакторе появляется меню «Готовые шаблоны», в нём вариант «Как в MyWork 2» для пяти видов актов (приём, приём по гарантии, пустой акт приёма, выдача, выдача после гарантии). Выбор заменяет шаблон в редакторе одним шагом с отменой; сохраняется как обычная правка.
6. **Шапка варианта собирается из того, что уже есть.** У точек в базе только название:
   - адреса точек с часами и телефонами — `{фирма.сведения}` (многострочный текст в «Документы и реквизиты»);
   - строка реквизитов — `{фирма.реквизиты}`;
   - «ссылка на страницу мастерской» — QR-код `{ссылка.yandex_maps}` справа (без адреса не печатается; в блоке можно выбрать другую ссылку).
   - Отдельные адрес, часы и телефон у точки — новая строка в «Идеях» README.
7. **Модель v5** (`TEMPLATE_FILE_VERSION = 5`, все новые поля с `#[serde(default)]`):
   - `Layout::TwoAcross` — A4 альбомный: экземпляр сервиса слева, клиента справа, между ними вертикальная пунктирная линия разреза. Если экземпляр не влезает по высоте, каждый идёт на свой лист (в той же ширине половины), как у `TwoPerA4`. Требует A4 альбомный (`requires_a4_landscape`); для наклейки и калибровки — `not_allowed`.
   - `Text.frame` — текст в рамке 0,6 pt на всю ширину колонки, поля внутри 2 мм по горизонтали и 1,5 мм по вертикали.
   - `Text.numbered` — после подстановки каждая непустая строка становится пунктом списка «1.», «2.», …; номер, набранный в начале строки (`1.`, `1)`, `12. `), убирается. `one_line` главнее: при нём нумерация не действует. Выравнивание у списка всегда по левому краю.
   - `Fields.grid` — таблица в полной сетке 0,4 pt (и в пустом бланке).
8. **Справка — диалог «Справка по Typst-коду»** (`Dialog size="lg"`), кнопка под редактором кода. Разделы:
   - что это за блок и когда он нужен;
   - значение поля;
   - условие;
   - таблица;
   - QR-код;
   - отступ;
   - только в одном экземпляре;
   - ограничения.
   Примеры кода лежат в `apps/ui/src/lib/templates/typst-snippets.json`, подписи и пояснения — в `ru.ts`.
9. **Бейджи** — ряд `InsertChip` под полем «Экземпляры» блока «Typst-код». У бейджа значок вставки (`TextCursorInput`), при наведении — подсказка с кодом.
   - Постоянные бейджи: «Номер заказа», «ФИО клиента», «Телефон клиента», «Устройство», «Дата приёма», «Логотип», «Отступ», «Только в экземпляре клиента», «Только в экземпляре сервиса».
   - Плюс «QR-код <имя>» для каждой включённой ссылки и «Другое поле…» — бывшая кнопка «Вставить поле», теперь последним бейджем того же ряда.
   - Внутри кода (`#{…}`, `if … {…}`) вставляется вариант без `#`.

## Global Constraints

- Встроенные ссылки (по порядку): «Яндекс Карты» `yandex_maps`, «2ГИС» `2gis`, «Telegram» `telegram`, «MAX» `max`. Не больше 20 ссылок, имя до 60 знаков, адрес до 500.
- Сохранённые до 8.3 шаблоны печатаются с теми же адресами: `{фирма.телеграм}`, `{фирма.гугл_карты}`, `{фирма.яндекс_карты}`, `v("firm.telegram")`, `qr-image("firm.telegram", …)` и то же для двух других.
- Выпущенные миграции не меняются, только добавляются новые. Изменение стартовых данных — только новой миграцией данных.
- Любая запись в БД — только через `Core::begin_write()`; права проверяет `mw-core`; каждый тест с БД идёт по `all_backends()`.
- Каждое изменение модели повышает `TEMPLATE_FILE_VERSION`; новые поля модели — с `#[serde(default)]`; `Template::validate` не сужать.
- Шаблоны пишутся только через `Core::save_document_template`.
- Данные заказа и ссылки никогда не становятся разметкой Typst — только `data.json` и виртуальные `barcode.svg`, `logo.png`, `qr-<имя>.svg`.
- Свой Typst-код строится только процессом-рендерером. Ограничения: 5 с на документ (`CODE_DOCUMENT_LIMIT`), без сети и чужих файлов; до 20 000 знаков в блоке и 50 000 на шаблон.
- Типы API — типы `mw-core`/`mw-domain` с `Serialize`/`Deserialize`, `ts_rs::TS`, `utoipa::ToSchema`. Входные — с `deny_unknown_fields`, каждое поле обязательно (тест `request_bodies_require_every_field`), `#[ts(export)]` не ставить.
- После изменения API: `MW_UPDATE_CONTRACT=1 cargo test -p mw-api --test contract -- --test-threads=1`, затем `cargo test -p mw-api --test contract` без переменной; `openapi.json` и `bindings/` — в том же коммите.
- `SEARCH_INDEX_VERSION` не трогается: `normalize_search` и построители `search_text` не меняются.
- Фото актов MyWork 2 и реквизиты с них в репозиторий не кладутся. В образцах только вымышленные данные из `fields.rs`.
- Интерфейс:
  - Svelte 5 на рунах, обработчики — пропсы `on…`;
  - импорты `#lib/...` с расширениями, типы API — `import type` из `$api/...`;
  - цвета и размеры — только токены `tokens.css`;
  - тексты — в `ru.ts`;
  - иконки `@lucide/svelte` по одной;
  - новые компоненты — в `#lib/ui/` с разделом на витрине `/design`;
  - `fetch` — только в `src/lib/api/client.ts`;
  - сквозные тесты — Chromium и WebKit, по ролям и подписям, данные через API с `uniq()`.
- Перед коммитом зелёное:
  - `cargo fmt --all --check && cargo clippy --workspace --all-targets -- -D warnings && cargo check --workspace && cargo test --workspace`;
  - в задачах с интерфейсом ещё `cd apps/ui && npm run verify && npm run test:e2e`.

## Review Focus

1. **Шаблон, сохранённый до 8.3, печатает те же адреса после миграции.** Это QR `{фирма.телеграм}`, текст `{фирма.яндекс_карты}`, код `qr-image("firm.telegram", 20mm)` и `v("firm.google_maps")`. Тесты: `firm_links_migration` (задача 1) и `legacy_link_substitutions_print_as_before` (задача 2).
2. **Выключенная ссылка, пустой адрес или `{ссылка.x}` удалённой ссылки.** QR не печатается и места не занимает, в тексте пусто, а не `{ссылка.x}`. Тесты: `disabled_or_missing_link_prints_nothing` (задача 2).
3. **Переименование ссылки и перестановка списка не ломают шаблоны.** Тест: `renamed_link_keeps_printing` (задача 2).
4. **Условия, уже пронумерованные вручную.** Строки вида «1. …», «2) …», пустые строки и CRLF дают один чистый список без двойных номеров и пустых пунктов. Тест: `numbered_text_strips_typed_numbers_and_blank_lines` (задача 3).
5. **Длинные условия не влезают в половину альбомного листа.** Тогда каждый экземпляр идёт на свой лист, ничего не обрезано. При этом вариант «Как в MyWork 2» на образце помещается на один лист. Тесты: `two_across_overflow_puts_each_copy_on_its_sheet` (задача 3), `mywork2_presets_fit_one_landscape_sheet` (задача 4).
