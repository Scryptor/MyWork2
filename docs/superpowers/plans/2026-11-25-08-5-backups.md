# План 8.5. Резервные копии

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** резервные копии данных программы:
- автокопия раз в день, пока программа открыта;
- ручная копия кнопкой;
- хранение N последних автокопий;
- восстановление из копии при следующем запуске, со страховочной копией текущих данных;
- подраздел «Настройки → Резервные копии»;
- настройки `EveryDayBackup` и `backupPath` из MyWork 2.

**Architecture:**
- Копия — папка `<папка копий>/<ГГГГММДД-ЧЧММСС>/`. Внутри:
  - `mywork.db` — снимок `VACUUM INTO`;
  - `attachments/` — файлы вложений; файл, который уже был в прошлой копии, ставится жёсткой ссылкой на него;
  - `mywork-backup.json` — описание копии.
  Копия собирается в `.partial-<штамп>/` и переименовывается в конце: оборванная копия не выглядит целой.
- Делает и восстанавливает копии модуль `mw-core::backups`. Он работает только с SQLite в папке данных; файлы обходит `mw-core::attachments::tree`.
  Настройки копий — файл `backup-settings.json` в папке данных, а не таблица `settings`. Это свойство компьютера, и восстановление его не откатывает.
- Восстановление отложенное, потому что пул базы закрывается только при выходе:
  - запрос пишет отметку `restore.json`;
  - при следующем запуске, до подключения к базе, `apply_pending_restore` по шагам: подготовка копии в `.restore/`, перенос текущих данных в страховочную копию, перенос копии на место;
  - каждый шаг можно повторить, поэтому оборванное восстановление доходит до конца при следующем запуске.
  Программа для компьютера перезапускается сама командой Tauri. Серверу `mw-server` перезапуск даёт тот, кто его запускает.
- Автокопию проверяет фоновая задача в `Server::serve`: через 2 минуты после запуска, затем раз в час. Копия делается, если сегодня автокопии ещё не было.
- API — раздел `backup_routes`, только на сервере на этом компьютере (loopback), как импорт.
  Командная строка: `mw-server backup` и `mw-server restore <папка>`.

**Tech Stack:** Rust (mw-db/SeaORM + sqlx SQLite, mw-core, mw-api/Axum + utoipa + ts-rs, mw-server/clap, Tauri 2), SvelteKit 3 + Svelte 5 (руны), Playwright. Новых зависимостей нет.

## Решения плана

1. **Что в копии.**
   - База — `VACUUM INTO` в `mywork.db`.
   - Вложения — дерево `attachments/`. Пропускаются:
     - верхняя папка `drafts` (черновики живут сутки);
     - любые имена, начинающиеся с точки (`.import-*`, `.DS_Store`);
     - символические ссылки.
   - Шрифты, отчёты импорта, журналы и `local.json` в копию не входят.
   - Сначала снимок базы, потом файлы. Так файл, добавленный во время копии, станет лишним, но не пропадёт строка без файла. Файл, удалённый между снимком и обходом, в копию не попадёт — это допустимо.
2. **Где копии.**
   - По умолчанию — `<папка данных>/backups/`, рядом с копиями импорта.
   - Можно выбрать свою папку: полный путь к существующей папке, в которую можно писать, вне папки данных.
   - Нет выбранной папки на месте (флешку вынули) — автокопия идёт в папку по умолчанию с пометкой, как в MyWork 2. Ручная копия в таком случае отказывает. Экран показывает копии из папки по умолчанию и пишет, что выбранной папки нет.
3. **Имя и описание.**
   - Имя папки — `Core::now()` в виде `%Y%m%d-%H%M%S`; занято — `-2`, `-3`.
   - `mywork-backup.json`:
     ```json
     { "format": 1, "kind": "auto", "created_at": "2026-11-25T18:00:00", "app_version": "0.0.3",
       "source": "<канонический путь папки данных>", "database_bytes": 0, "files": 0, "files_bytes": 0 }
     ```
   - Виды: `auto`, `manual`, `before_restore`.
   - Копией считается только папка с этим файлом. Копии импорта (без описания), чужие папки и `.partial-*` в списке не показываются и не удаляются.
4. **Жёсткие ссылки.**
   - Файлы вложений не меняются после записи: имена — uuid.
   - Если в последней своей копии той же папки есть файл с тем же путём и размером, в новой копии он становится жёсткой ссылкой на него (`std::fs::hard_link`). Ошибка ссылки (FAT, другой диск) — обычное копирование.
   - Так 10 автокопий занимают место одной копии файлов плюс 10 баз.
5. **Автокопия.**
   - Включена по умолчанию, как `EveryDayBackup`.
   - Делается, если всё сразу:
     - включена;
     - база — SQLite в папке данных;
     - копия сейчас не идёт;
     - в папке копий нет своей автокопии с датой `created_at` = сегодняшней (`Core::now()`).
   - Своя — та, у которой `source` = эта папка данных.
   - После автокопии остаются `keep` последних своих автокопий этой папки (по умолчанию 10, от 1 до 100). Ручные, страховочные, чужие и копии импорта не удаляются никогда.
   - Копии при закрытии программы нет: закрытие ждёт сервер не больше 30 с.
6. **Восстановление.**
   - Запрос (`request_restore`):
     - копия есть в списке;
     - `PRAGMA quick_check` даёт `ok`;
     - в её `seaql_migrations` нет миграций, которых не знает программа.
     Тогда пишется `restore.json`: путь копии, её описание, время запроса и кто запросил.
   - При запуске `apply_pending_restore(data_dir)` идёт по шагам, записывая шаг в `.restore/phase.json`:
     1. **Подготовка.** `.restore/` создаётся заново. Туда копируются `mywork.db` копии (и `mywork.db-wal`, если есть) и её `attachments/` — копированием, не ссылками. Копия проверяется так же, как при запросе. Выбирается имя страховочной копии — штамп времени запроса. Шаг `copied`.
     2. **Перенос текущих данных.** `mywork.db`, `mywork.db-wal`, `mywork.db-shm` и `attachments/` переименовываются в `<папка данных>/backups/<имя>/` — только то, что ещё на месте. Пишется описание `before_restore` с `created_at` = времени запроса. Шаг `moved_aside`.
     3. **Перенос копии.** `attachments/`, `mywork.db` и `mywork.db-wal` из `.restore/` переименовываются на место — только то, что ещё в `.restore/`. `.restore/` и `restore.json` удаляются, пишется `restore-result.json`.
   - Ошибка до шага 2: копии нет, повреждена или от новой версии. Тогда пишется `restore-result.json` с ошибкой, удаляются `restore.json` и `.restore/`, программа запускается с прежними данными.
   - Ошибка на шагах 2–3 — ошибка запуска. Отметка остаётся, и следующий запуск продолжит с записанного шага. Без базы программа не открывается и пустую базу не создаёт.
   - Страховочная копия всегда в папке по умолчанию: переименование не выходит за пределы диска.
   - После восстановления сервер пишет в журнал действий `backup.restored` от имени того, кто запросил.
7. **Права.**
   - Обзор, ручная копия, настройки, настройки MyWork 2 — `SettingsManage`.
   - Восстановление, его отмена и удаление копии — `SettingsManage` и `UsersManage`, как импорт: копия заменяет и пользователей.
   - API — только на loopback, иначе 403 «Резервные копии настраиваются на компьютере, где работает сервер».
8. **PostgreSQL и база по адресу.**
   - Копии делаются только для SQLite-файла в папке данных: сервер включает их через `Core::with_backups()`, когда `database_url` не задан.
   - Иначе обзор отвечает `supported: false` с причиной. Все действия — правка настроек, копия, удаление, выбор настроек MyWork 2, запрос и отмена восстановления — отвечают `CoreError::Unavailable` с той же причиной. `run_auto_backup_if_due` отвечает `Ok(None)`.
   - `pg_dump` — в план 9.
9. **Настройки MyWork 2.**
   - Берутся из `legacy_rows` с `source = "Config.ini"`:
     - `[CHECKBOX] EveryDayBackup`: включено, если значение ровно `Checked` или строки нет, как в MyWork 2;
     - `[<любая секция>] backupPath`: все непустые полные пути по порядку строк, без повторов.
   - Пока пользователь не ответил (`legacy_reviewed = false`), экран предлагает «Взять настройки MyWork 2» и «Не нужно».
   - «Взять»:
     - ставит `auto` из `EveryDayBackup`;
     - папкой ставит первый путь, который на этом компьютере — существующая папка, проходящая проверки решения 2; нет такой — папка не меняется;
     - отмечает `legacy_reviewed`.
   - «Не нужно» только отмечает.
10. **Журнал действий:** `backup.created` (ручная копия), `backup.deleted`, `backup.restore_requested`, `backup.restore_cancelled`, `backup.restored`, `backup.settings` (сводка изменённого). Автокопии в журнал не пишутся, только в лог.
11. **Ход копии.** Одна копия за раз (`tokio::sync::Mutex` в `Core`). Второй запуск — `CoreError::InUse("Копия уже делается — дождитесь её")`.
    - Ручная копия из API идёт фоном (`spawn_background`) и сразу отвечает 202 с ходом `BackupJob`. Обзор отдаёт последний ход с запуска сервера.
    - Остановка сервера прерывает копию между файлами (`shutdown_token`), удаляет `.partial-*`, и ход получает ошибку «Копия прервана: программа закрывается».
12. **Вне плана** (в `README.md`, «Идеи»):
    - окно восстановления, когда программа не запускается;
    - вернуть данные к состоянию до импорта: копии импорта без описания;
    - `pg_dump`;
    - смена папки данных.
    До окна восстановления копия — обычная папка: подсказка экрана говорит, как вручную положить `mywork.db` и `attachments` в папку данных.

## Global Constraints

- Время — только `Core::now()`: имена копий, `created_at`, «сегодня». Срок между проверками автокопии — `tokio::time::interval`. `apply_pending_restore` идёт до `Core` и время не читает: берёт время запроса из `restore.json`. Исключение — команда `mw-server restore`, когда текущая база не открывается: тогда время запроса — UTC системы (решение задачи 3).
- Любая запись в БД — через `Core::begin_write()`: журнал действий.
- Файлы вложений — только через `mw-core::attachments` (`attachments/tree.rs`). Пути строк — через `store::resolve`, если код их касается. Символические ссылки не обходятся.
- Каждый тест с БД идёт по `all_backends()`. Для PostgreSQL проверяется отказ (`supported: false`, `CoreError::Unavailable`). Файловая SQLite — временная папка и `mw_db::connect(&mw_db::sqlite_url(&path))`, как в `crates/mw-core/tests/sqlite_file_concurrency.rs`. PostgreSQL — `MW_TEST_PG_URL=postgres://postgres:postgres@localhost:55432/postgres`.
- Выпущенные миграции не меняются. Миграций в этом плане нет.
- `Actor::for_tests` и `Core::db()` — только в тестах. Сервер и командная строка берут `Actor::unrestricted(…)`.
- Типы API:
  - `Serialize`/`Deserialize`, `ts_rs::TS`, `utoipa::ToSchema`;
  - входные — с `deny_unknown_fields`, правки — `patch::present`/`patch::nullable`;
  - `#[ts(export)]` не ставить;
  - имена уникальны во всём проекте (ts-rs кладёт привязки по имени): `BackupKind`, `BackupCopy`, `BackupSettings`, `BackupSettingsPatch`, `BackupJob`, `BackupRestorePending`, `BackupRestoreResult`, `BackupLegacySettings`, `BackupOverview`, `BackupRestoreRequest`, `BackupLegacyChoice`.
- Маршруты — функцией `#[inline(never)] fn backup_routes()` в `crates/mw-api/src/routes/mod.rs`. Тест `crates/mw-api/tests/stack.rs` зелёный.
- После изменения API: `MW_UPDATE_CONTRACT=1 cargo test -p mw-api --test contract -- --test-threads=1`, затем `cargo test -p mw-api --test contract` без переменной. `openapi.json` и `bindings/` — в том же коммите.
- Коды ошибок (`FieldError`, текст — в `message_ru` и в шапке списка кодов `crates/mw-domain/src/validation.rs`, проверка — в `crates/mw-core/tests/api_types.rs` `field_error_messages_are_russian`):
  - `folder_relative` у `folder`: «Укажите полный путь к папке»;
  - `folder_missing` у `folder`: «Такой папки нет на этом компьютере»;
  - `folder_inside_data` у `folder`: «Папка копий не может лежать внутри папки данных — выберите другую или оставьте папку по умолчанию»;
  - `folder_read_only` у `folder`: «В эту папку нельзя записать»;
  - `backup_missing` у `name`: «Такой копии нет»;
  - `backup_damaged` у `name`: «Копия повреждена — выберите другую»;
  - `backup_too_new` у `name`: «Копия сделана более новой версией программы — сначала обновите программу»;
  - `backup_pending` у `name`: «Эта копия ждёт восстановления — сначала отмените его»;
  - `keep` вне 1–100 — существующий `out_of_range`.
- Тексты отказов (`CoreError`):
  - PostgreSQL: «Для PostgreSQL резервные копии делает pg_dump по расписанию на сервере»;
  - база по адресу: «Резервные копии делаются только для базы в папке данных»;
  - копия идёт: «Копия уже делается — дождитесь её».
- Зависимостей не добавлять: жёсткие ссылки и обход — `std::fs`, открыть папку — уже подключённый в программе для компьютера `open`.

## Review Focus

1. **Программу закрыли или она упала посреди восстановления.**
   - Следующий запуск доводит восстановление до конца с записанного шага.
   - В папке данных никогда не остаётся «ни базы, ни отметки».
   - Пустая база не создаётся.
   Тест: `an_interrupted_restore_finishes_on_the_next_start` (задача 2).
2. **Выбранная папка копий пропала** (флешка, сетевой диск).
   - Автокопия уходит в папку по умолчанию с пометкой.
   - Ручная копия отказывает `folder_missing`.
   - Экран показывает копии из папки по умолчанию.
   Тест: `a_missing_folder_sends_the_auto_copy_to_the_default_one` (задача 1).
3. **Копия повреждена или сделана более новой версией.** Отказ при запросе. При запуске — отказ без единого переноса: прежние данные на месте, `restore-result.json` с ошибкой. Тесты: `a_damaged_or_newer_copy_is_not_restored` (задача 2), `inspect_tells_good_damaged_and_newer_copies` (задача 2).
4. **Хранение N последних не трогает чужое.** Ручные, страховочные копии, копии импорта без описания, копии другой папки данных и посторонние папки остаются. Тест: `auto_copy_is_made_once_a_day_and_keeps_the_last_n` (задача 1).
5. **Копия оборвалась** (программу закрыли, упал диск).
   - Обрывок не виден в списке и не служит источником ссылок.
   - Его убирает следующая копия.
   - Ход сообщает об обрыве.
   Тесты: `an_interrupted_copy_is_not_listed_and_is_cleaned_up` (задача 1), `copy_tree_stops_when_cancelled` (задача 1).

**Files:**
- Create: `crates/mw-core/src/attachments/tree.rs` (+ `pub(crate) mod tree;` в `crates/mw-core/src/attachments/mod.rs`)

- Modify: `crates/mw-core/src/lib.rs` (`pub mod backups;`, `pub use` типов), `crates/mw-core/src/core.rs` (поля `backups_on: bool`, `backup_lock: Arc<tokio::sync::Mutex<()>>`, `backup_job: Arc<std::sync::Mutex<Option<BackupJob>>>`; `pub fn with_backups(self) -> Core`)

**Interfaces:**
- Produces (`mw-core::attachments::tree`):
