## Идеи для программы

### Приём и выдача

- [ ] **Умные списки в форме «Новый заказ».** Заменить ряды бейджей «Комплектность» и «Состояние» выпадающими списками. При открытии первыми показывать значения, которые чаще всего встречаются в заказах. При вводе предлагать автодополнение. Способ подсчёта частоты предстоит выбрать. Формирование списков при запуске для объёма больше 100 записей и подсчёт по запросу для меньшего объёма — предварительный вариант. При планировании сравнить запросы с индексами и отдельную таблицу частот с автоматическим обновлением при изменении заказов, по расписанию или в простое. Если понадобится порог, уточнить, какие записи считать и как обрабатывать ровно 100.
- [x] **Приём с номера телефона.** При вводе номера показать найденных клиентов и дать выбрать нужного по ФИО. Уже есть в форме приёма.
- [x] **Предупреждение о проблемном клиенте при приёме.** Отметка о чёрном списке видна на карточке клиента до сохранения заказа. Уже есть в форме приёма.
- [ ] **Быстрые клавиши для «Неисправности» и «Выполненных работ».** Уточнить действия для каждого поля при планировании.
- [ ] **Точка выдачи при переводе в «Готов».** Дать выбрать филиал, если клиент заберёт устройство в другом месте. Общий переключатель точек уже есть.
- [ ] **Звонок по номеру клиента из программы.** При клике на номер инициировать вызов с рабочего телефона приёмки.

### Склад, цены и расчёты

- [ ] **Остатки запчастей при приёме.** Показывать доступные детали и их количество по выбранной модели устройства. Рассмотреть компактный сворачиваемый блок.
- [ ] **Списание из заказа при переводе в «Готов».** Дать перейти из заказа к складским позициям и списать использованные детали. Списание в заказ предусмотрено в плане склада.
- [ ] **Оповещение о закончившихся позициях.** Проверить сообщение пользователя о несработавшем оповещении, уточнив версию и условия. В спецификации предусмотрено напоминание о минимальном остатке.
- [ ] **Интеграция склада с фискальным регистратором.**
- [ ] **Цены запчастей у поставщиков.** При оформлении показывать цены из выбранных источников с учётом розничных, оптовых и сервисных условий. Способ получения цен выбрать при планировании.
- [ ] **Процент оплаты мастера.** Настраивать индивидуальные ставки, в том числе по типу работы. Примеры — замена модуля, переклейка и сложная пайка.
- [ ] **Ориентир по стоимости ремонта с помощью ИИ.** Показывать примерные цены на похожие работы в городе или регионе. Продумать источник и актуальность цен.

### Уведомления и документы

- [ ] **Уведомления и напоминания клиентам в Telegram или MAX.** Рассмотреть бота и QR-код на акте приёмки для подключения клиента к уведомлениям.
- [ ] **Статус заказа на сайте мастерской.** Дать клиенту самостоятельно посмотреть, на каком этапе ремонт.
- [ ] **Поиск заказа по коду с документа.** Штрихкод и поиск сканером предусмотрены в спецификации печати. Рассмотреть QR-код заказа в актах и других документах.
- [ ] **Логотип мастерской на актах.** Добавление своего логотипа предусмотрено в редакторе шаблонов.

### Доступ и настройка программы

- [ ] **Одна база на нескольких компьютерах.** Пользователям нужна возможность работать с одними и теми же заказами на разных рабочих местах. Сетевой режим предусмотрен в плане 9.
- [ ] **Работа со смартфона.** Учесть сценарий выездного мастера, у которого нет рабочего компьютера. Мобильный доступ предусмотрен в плане 10.
- [ ] **Свои группы и перечни услуг.** Дать мастерской настроить их под свой вид деятельности, например под автосервис.
- [ ] **Встроенный чат мастеров.** Дать мастерам общаться в программе, например спрашивать о прошивках и обсуждать ремонт.

## Заметки для следующих планов

- **План 5.4 (настройки и справочники):**
  - смена вида статуса, которым уже пользуются заказы, предупреждает;

- **План 5.5 (доводка заказов, клиентов и фото):** осталось только отложенное сознательно:
  - ширины и порядок колонок, `BlistColor`, `colorDiagnostik`, `colorCheckBox`, `Poloski` из `legacy_rows` (`Config.ini`) — не переносим: колонки новой таблицы другие и заполняют ширину, палитра — дизайн-система; значения остаются в `legacy_rows`;
  - клиенты: объединённый клиент по `?client=` показывает «Клиент удалён или объединён» без ссылки — сервер не хранит, куда ушёл источник (есть только запись журнала `client.merged` у оставшегося), нужна новая таблица или поле; новый клиент от принятого заказа появляется в списке после перезагрузки — строка обновляется только у уже показанного, перечитывать первую страницу после каждого заказа дороже, чем эта задержка;
  - переименование значения справочника так, что оно совпадает без учёта регистра с другим значением, даёт дубль — путь через объединение (t3c); отдельный разбор не нужен, пока дубли не встречаются;
  - гарантия: замена в заказах отклоняется, если меняет срок; смена срока только у невыданных заказов — отдельное действие с подсчётом в окне, не делаем, пока не попросят.

  - стадии «Чтение» и «Разбор» импорта не отменяются — они идут секунды, остановка программы их дожидается;
  - сквозного теста на перенос с заменой при первом запуске нет (нужен ещё один чистый сервер с администратором) — ветку проверяет vitest;
  - размер и положение окна не запоминаются;
