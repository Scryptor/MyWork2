Спецификация: [2026-11-11-mywork3-crossplatform-design.md](../specs/2026-11-11-mywork3-crossplatform-design.md).

пишется непосредственно перед выполнением, с учётом того, что получилось в предыдущем.

## Заметки для следующих планов

- **План 5:**
  - строить экраны по разделу 6 спеки интерфейса из компонентов плана 4; пункты раздела 12 спеки:
    - «Давно готовы» — по дате перехода в статус вида `ready` из истории, без неё — по дате приёма;
    - массовая смена статуса на вид `issued` спрашивает дату выдачи: «сейчас» или «не ставить» (сейчас массовое меню видов `issued` не содержит);
    - цвет статуса — одно из 12 имён палитры, сервер проверяет его при создании и правке;
    - «Мои виды» и черновик приёма — на устройстве;
    - относительные даты считаются от времени сервера, поправку даёт `ServerInfo`;
  - открывать панели и листы после того, как SvelteKit закончил фокусировку после навигации (иначе WebKit теряет курсор в поле); правильное решение — в `Sheet`;
  - `StatusPicker`: с `onchange` значением владеет родитель и может отклонить выбор; нет «Ещё ▾» при более чем 7 статусах; статусы без заказов в быстрых фильтрах уходят в «Ещё»;
  - панель массовых действий: «Мастер ▾», «Отметки ▾» и «Фильтры ▾» не построены;
  - несколько заказов с одним штрихкодом — диалог выбора;
  - выбор (списки, переключатели, статус) сохраняется сразу, текст — через 600 мс;
  - `DataTable`: родитель с определённой высотой (иначе рисует все строки); родитель сбрасывает `selected` при смене данных; `onendreached` срабатывает один раз на массив `rows` — на каждую страницу новый массив;
  - уведомления не реагируют на нажатия, пока открыто модальное окно bits-ui (отмена из уведомления за листом недоступна; смена статуса и сразу Ctrl K — отмена потеряна) — решить в плане 5; у `Dialog` нет запасного фокуса, если исчез элемент, открывший его;
  - дизайн-систему доделать в начале плана 5:
    - нет кнопки, которая может открывать меню или всплывающее окно (стиль `.trigger` повторён в 5 файлах);
    - `TextInput` не принимает `aria-label` вместо видимой подписи и не даёт поставить в себя фокус (фильтр списка по `/` — голый `input`);
    - Ctrl/⌘+Enter сделан двумя способами: `onkeydown` формы с `matchShortcut` и `registerHotkey` — оставить один;
  - формы перед отправкой проверяют `invalid` у `MoneyInput` и `DateInput`; `MoneyInput` берёт сумму при вводе, `DateInput` — при уходе из поля и Enter (в листе Esc в WebKit может потерять набранную дату — перевести на разбор при вводе);
  - `MoneyInput` и `PhoneInput` пересинхронизируют текст, когда `value` меняется снаружи: если сохранение асинхронное и ответ сервера придёт после новых нажатий, устаревшее значение затрёт набранное — держать в поле своё значение до ответа или отбрасывать устаревшие ответы (по `version`);
  - открытая подсказка съедает первое Esc в панели: bits-ui вызывает `preventDefault`, и стек слоёв уступает;
  - повторённые помощники вынести в общие: группировка разрядов (`money.ts`, `plural.ts`, `SelectionBar.svelte`), `dayNumber` (`date.ts`, `demo/orders.ts`), безопасный доступ к `localStorage` (5 копий);
  - сканер вне поля: `/`, `?` или строчная `n` в отсканированном тексте срабатывают как клавиши посреди скана (12-значных штрихкодов это не касается);
  - стрелки в `StatusPicker` сохраняют каждый пройденный статус (уведомление и запись истории на каждый) — выбор пробелом или склейка шагов;
  - экран отчёта импорта (`legacy_imports.report`) и запуск импорта из интерфейса — выбор папки Tauri-командой, долгая операция с прогрессом;
  - десктоп и сервер: импорт командой при запущенном сервере оставляет у сервера старый кэш настроек — перезапуск; импорт из интерфейса должен идти в процессе сервера;
  - таблица `attachments` и регистрация файлов из `attachments/orders/<id>/` по строкам `legacy_rows` (`ClientFiles`);
  - ширины и порядок колонок, `BlistColor`, `colorDiagnostik`, `colorCheckBox`, `Poloski` из `legacy_rows` (`Config.ini`);
  - список телефонов клиента и гарантия «текст + срок» в формах;
  - выбор из нескольких заказов по одному штрихкоду.
  - настройка точки по умолчанию может указывать на архивную точку — считать её пустой;
  - импорт в процессе сервера — в отдельной задаче (`tokio::spawn` + `spawn_blocking` для файлов): отменённый запрос во время записи удаляет промежуточную папку;
  - гарантия: «0 мес» и «0 дней» — обе «без гарантии», проверять `value == 0` независимо от единицы.
  - сортировка по бренду/модели/мастеру сейчас по кодовым точкам с учётом регистра — нужны нормализованные колонки сортировки;
  - смена вида статуса, которым уже пользуются заказы, должна предупреждать.
  - CORS для источников Tauri (`tauri://localhost`, `http://tauri.localhost`); правило «изменяющие запросы только с JSON» остаётся;
  - решено: интерфейс берёт `crates/mw-api/bindings/` через псевдоним `$api` (только `import type`);
  - логи в файл в папке данных;
  - десктоп запускает сервер через `mw_server::Server` на `127.0.0.1:0`;
  - даты в OpenAPI помечены `format: date-time`, но в API это местное время без смещения — клиент не должен добавлять `Z`/смещение;
  - `ApiConfig` строить только из фактического адреса прослушивания (закрыть поле `loopback`), чтобы десктоп не включил режим без входа на `0.0.0.0`.
- **План 6:** реквизиты и тексты договоров уже в настройках, в них может остаться HTML MyWork 2; размер штрихкода `[ACTS] BarcodeH/BarcodeW` и шаблоны `Shablon_*.htm` — в `legacy_rows`.
- **План 8:**
  - склад из `legacy_rows` (`Stock`, `StockMap`, `settings/Stock/*.txt`) и фото `attachments/stock/<id>/` — перенос в таблицы склада в импорт и для уже импортированных баз;
  - `Zatrati` заказов уже включают запчасти из `StockMap` — не задвоить;
  - отчёты по источнику — группировать без учёта регистра;
  - `backupPath`, `EveryDayBackup` из `legacy_rows`.
- **План 9:**
  - повторный импорт с заменой на PostgreSQL (копия — экспортом в SQLite); импорт на удалённый сервер — загрузка папки или архива;
  - за обратным прокси ограничитель попыток видит адрес прокси — нужен список доверенных прокси и `X-Forwarded-For`;
  - ограничитель считает IPv6 по одному адресу (/128) — для сервера в интернете считать по /64;
  - режим хоста (`0.0.0.0`) отключает режим без входа — интерфейс должен предложить создать администратора;
  - сервер на loopback за обратным прокси (nginx передаёт `Host` своего upstream) пропускает проверку `Host`, и режим без входа становится доступен снаружи — отказывать в режиме без входа при `Forwarded`/`X-Forwarded-For` или требовать пользователей;
  - попытка входа, отменённая по таймауту или обрывом соединения, остаётся засчитанной — нужен страж, прощающий попытку, если пароль не проверялся;
  - HTTPS и закрепление сертификата.
- **Общее:**
  - добавить в CI `cargo-deny` (лицензии и уязвимости зависимостей) — сейчас лицензии проверяются вручную.
