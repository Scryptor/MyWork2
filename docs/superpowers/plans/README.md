## Заметки для следующих планов

- **План 5.3 (масштаб и разные мониторы):**
  - проверка на 1280×720, 1366×768, 1440×900, 1728×1117 (MacBook Pro 16"), 1920×1080, 2560×1440, 3840×2160 и Windows 125/150 %;
  - плотнее по умолчанию: текст, строки, поля, меню, панели;
  - масштаб «Авто» по размеру окна с ручными шагами;
  - настройки внешнего вида этого компьютера (тема, размер, плотность) переезжают из «Настроек» в этот план;
  - сквозные снимки на нескольких размерах в обоих движках; ничего не наезжает и не уезжает за край.
- **План 5.4 (настройки и справочники):**
  - смена вида статуса, которым уже пользуются заказы, предупреждает;
  - гарантия: `warrantyUntil` (`intake/draft.ts`) считает месяцами любую единицу, кроме дней — при новой единице поправить;
  - ширины и порядок колонок, `BlistColor`, `colorDiagnostik`, `colorCheckBox`, `Poloski` из `legacy_rows` (`Config.ini`);
  - доводка интерфейса:
    - карточка: две выборки истории на каждую сохранённую версию; `OrderHistory` перечитывается на каждой версии;
    - карточка: если за время листания истории пришло 500 и больше новых записей, страница повторяется;
    - карточка: неудачная следующая страница статусов и сроков показана как пустая история;
    - карточка пересоздаётся при переходе через ширину 1024 px и теряет фокус;
    - смена заказа в редакторе с нерешённым конфликтом теряет спорные значения без предупреждения;
    - `WarrantyCaseDialog` собирает дату ISO вручную (`${date}T00:00:00`) — перевести на `#lib/format/date.js`;
    - массовые действия: меню остаются доступны, пока идёт пакет;
    - массовые действия: выбор снимается, даже если не удался ни один заказ;
    - правки пропадают при выходе из системы без сброса очереди; одиночки приложения переживают выход и вход другим пользователем;
    - массовая отмена возвращает значения на момент списка; `StatusPicker`: Shift+стрелка выбирает через родной переключатель, нет «Ещё ▾» при более чем 7 статусах;
    - `Toaster` мешает выделять текст; открытая подсказка съедает первое Esc в панели;
    - `DataTable`: родитель с определённой высотой, сброс `selected` при смене данных, `onendreached` — раз на массив `rows`;
    - `order_values` без SQL `LIMIT`;
    - история заказа (`order_history`) отдаётся и для удалённого заказа;
    - статические файлы отдаются с `no-store`, а отсутствующий `/_app/...` возвращает `index.html`;
    - уведомления не реагируют на нажатия, пока открыто модальное окно bits-ui; у `Dialog` нет запасного фокуса, если исчез открывший его элемент.
    - фото и файлы: «Повторить» у неудавшейся загрузки обходит предел в 10 фото и блокировку; «Отмена», обновление и подстановка клиента оставляют фото старого ключа до очистки через 24 ч;
    - `POST /orders` мог бы помечать повтор (заголовок ответа), чтобы приём знал, что заказ уже был;
    - кэш адресов вложений держит 25 МБ оригиналы и миниатюры под одним пределом 200;
    - клиенты: объединённый или удалённый клиент по `?client=` даёт бесполезное «Повторить»; панель показывает прежнего клиента, пока грузится следующий; созданный заказ перечитывает первую страницу клиентов;
    - окно объединения: до 20 запросов на открытие (в элементах списка уже есть `orders_count`);
- **План 5.5 (десктоп, первый запуск, импорт):**
  - десктоп запускает сервер через `mw_server::Server` на `127.0.0.1:0` и раздаёт интерфейс; логи в файл в папке данных;
  - экран отчёта импорта (`legacy_imports.report`) и запуск импорта из интерфейса — выбор папки Tauri-командой, долгая операция с прогрессом;
  - импорт командой при запущенном сервере оставляет у сервера старый кэш настроек — перезапуск; импорт из интерфейса идёт в процессе сервера;
  - импорт в процессе сервера — в отдельной задаче (`tokio::spawn` + `spawn_blocking` для файлов): отменённый запрос во время записи удаляет промежуточную папку;
  - e2e: обработчики сигналов в `server.mjs` ставятся после `create-admin`; SIGKILL оставляет `mw-server` сиротой.
- **План 6:** реквизиты и тексты договоров уже в настройках, в них может остаться HTML MyWork 2; размер штрихкода `[ACTS] BarcodeH/BarcodeW` и шаблоны `Shablon_*.htm` — в `legacy_rows`.
- **План 8:**
  - склад из `legacy_rows` (`Stock`, `StockMap`, `settings/Stock/*.txt`) и фото `attachments/stock/<id>/` — перенос в таблицы склада в импорт и для уже импортированных баз;
  - `Zatrati` заказов уже включают запчасти из `StockMap` — не задвоить;
  - отчёты по источнику — группировать без учёта регистра;
  - `backupPath`, `EveryDayBackup` из `legacy_rows`.
- **План 9:**
  - повторный импорт с заменой на PostgreSQL (копия — экспортом в SQLite); импорт на удалённый сервер — загрузка папки или архива;
  - за обратным прокси ограничитель попыток видит адрес прокси — нужен список доверенных прокси и `X-Forwarded-For`;
  - ограничитель считает IPv6 по одному адресу (/128) — для сервера в интернете считать по /64;
  - режим хоста (`0.0.0.0`) отключает режим без входа — интерфейс должен предложить создать администратора;
  - сервер на loopback за обратным прокси (nginx передаёт `Host` своего upstream) пропускает проверку `Host`, и режим без входа становится доступен снаружи — отказывать в режиме без входа при `Forwarded`/`X-Forwarded-For` или требовать пользователей;
  - попытка входа, отменённая по таймауту или обрывом соединения, остаётся засчитанной — нужен страж, прощающий попытку, если пароль не проверялся;
  - HTTPS и закрепление сертификата.
- **Общее:**
  - добавить в CI `cargo-deny` (лицензии и уязвимости зависимостей) — сейчас лицензии проверяются вручную.
  - даты в OpenAPI помечены `format: date-time`, но в API это местное время без смещения — клиент не должен добавлять `Z`/смещение;
  - ограничитель входа и e2e `--repeat-each`: прогон даёт около 4 неудачных входов, предел — 20.
  - загруженный `.svg` отдаётся inline (`image/svg+xml`), защищает только CSP `sandbox` — inline отдавать только растровые типы;
  - `discard_draft` на сервере удаляет всю папку `attachments/drafts/<ключ>`: если перенос файлов черновика в заказ оборвался на середине, файлы заказа из этой папки пропадут — удалять только файлы строк, ещё лежащих в черновике;
  - на телефоне в списке клиентов нет множественного выбора: объединение — через «Объединить с…» (учесть в плане 10).
