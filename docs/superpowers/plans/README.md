## Заметки для следующих планов

- **План 5.4 (настройки и справочники):**
  - смена вида статуса, которым уже пользуются заказы, предупреждает;
  - гарантия: `warrantyUntil` (`intake/draft.ts`) считает месяцами любую единицу, кроме дней — при новой единице поправить;
- **План 5.5 (доводка заказов, клиентов и фото):** осталось только отложенное сознательно:
  - ширины и порядок колонок, `BlistColor`, `colorDiagnostik`, `colorCheckBox`, `Poloski` из `legacy_rows` (`Config.ini`) — не переносим: колонки новой таблицы другие и заполняют ширину, палитра — дизайн-система; значения остаются в `legacy_rows`;
  - клиенты: объединённый клиент по `?client=` показывает «Клиент удалён или объединён» без ссылки — сервер не хранит, куда ушёл источник (есть только запись журнала `client.merged` у оставшегося), нужна новая таблица или поле; новый клиент от принятого заказа появляется в списке после перезагрузки — строка обновляется только у уже показанного, перечитывать первую страницу после каждого заказа дороже, чем эта задержка;
  - переименование значения справочника так, что оно совпадает без учёта регистра с другим значением, даёт дубль — путь через объединение (t3c); отдельный разбор не нужен, пока дубли не встречаются;
  - гарантия: замена в заказах отклоняется, если меняет срок; смена срока только у невыданных заказов — отдельное действие с подсчётом в окне, не делаем, пока не попросят.
- **План 5.6 (десктоп, первый запуск, импорт):** осталось только отложенное сознательно:
  - вкладка без «Запомнить» сбрасывается, когда другой пользователь входит с «Запомнить»; вход другого без «Запомнить» (его сеанс — в своём `sessionStorage`) прежние вкладки не видят — общего места для такой метки нет;
  - разрешения окна (`capabilities`) открыты для `http://127.0.0.1:*`, а не для одного порта: чужие адреса в окно не пускает проверка переходов;
  - стадии «Чтение» и «Разбор» импорта не отменяются — они идут секунды, остановка программы их дожидается;
  - сквозного теста на перенос с заменой при первом запуске нет (нужен ещё один чистый сервер с администратором) — ветку проверяет vitest;
  - размер и положение окна не запоминаются;
- **План 10:**
  - мобильный браузер может выгрузить скрытую вкладку без `pagehide`: удаления фото, ждущие своего уведомления «Отменить» (6 с), тогда не уходят — фото остаётся и видно при следующем открытии; решить, отправлять ли их по `visibilitychange`.
  - прерванный импорт (программу закрыли или она упала во время переноса) показать при следующем запуске — ссылкой на его отчёт; сейчас о нём говорят только «Настройки → Импорт из MyWork 2».
- **План 5.7 (замечания автора: интерфейс):** осталось отложенное сознательно:
  - «Часовой пояс» стал выпадающим списком (`Select`) с названием впереди («Москва (UTC+03:00)»): первые буквы, набранные в открытом списке, находят пояс по названию («Сам» → «Самара»); отдельного поля поиска не будет — уточнить у автора, хватает ли этого;
  - в отчёте импорта источник `StatesMap` (журнал смен статусов) подписан «Статус» — читается как номер статуса; подписать «История статусов» (`ru.importReport.sources`, e2e ждёт `^Статус · 7`);
  - «Принять по гарантии» находит статус по названию «Принят по гарантии» — подсказка предупреждает не переименовывать; нужна связь по коду или по виду;
  - подсказка во всплывающей панели (`Popover`) рисуется под панелью — поэтому внутри «Фильтров» подсказок нет; поправить слои, потом добавить (например, «Точка»);
  - на сенсорном экране выравнивание с подсказкой проверено у `Field`; у `Switch`, `ChipGroup`, `Section` значок стоит иначе — проверить при первом случае сдвига;
  - около девяти одинаковых обёрток «текст + `HelpHint`» (заголовки страниц и разделов) — свести в один компонент `#lib/ui`;
  - мастер переноса отличает оборванную проверку по тексту ответа сервера (503) — нужен отдельный код ошибки;
  - заголовки колонок `CatalogRows` без роли `columnheader`; при неудачной загрузке справочника гарантий список молча показывает только «Не задана» и сохранённое значение.
- **План 5.8 (пользователи, роли и мастера):**
  - мастера — учётные записи, а не справочник (решение автора, 2026-11-20): в сервисе есть роли — мастер, приёмщик, администратор и т. п.; мастер сам работает в программе — смотрит заказы, меняет статусы, пишет комментарии. Мастер заказа — пользователь с ролью/отметкой «Мастер» (можно и без входа — для тех, кто в программе не работает); заказ хранит ссылку на пользователя и имя текстом для истории; при импорте имена мастеров из заказов и `masters.txt` сопоставляются с пользователями MyWork 2 по имени, остальные становятся пользователями без входа; раздел «Мастера» уходит из «Справочников». Готовые роли «Мастер», «Приёмщик», «Администратор» с понятными наборами прав; права любой роли, в том числе готовой, автор меняет сам галочками (что может, что нет), можно заводить свои роли; защита от потери доступа — сервер не даёт снять «Пользователи и права» с последней роли, где оно есть у действующего пользователя. Нужно для отчётов и доли мастера (план 8);
  - комментарии мастера к заказу: проверить, хватает ли нынешнего поля «Комментарий» и истории, или нужна лента комментариев с автором и временем;
- **План 5.9 (карточка заказа):**
  - счёт использования справочника (`mw-core/src/usage.rs`) и переименование/объединение значений вместе с заказами (`dictionaries_rewrite.rs`) делят поля-списки только по запятым, а «Неисправность» и «Выполненные работы» в MyWork 3 — многострочные поля: пункты, введённые по одному в строке, не считаются и не переименовываются; пункт с точкой в конце («Шумит.») — тоже отдельный текст. Решить вместе с полями карточки (делить и по строкам или вводить пункты только через запятую);
  - карточка заказа — выезжающая панель и полный режим: отдельно продумать дизайн (навык `frontend-design`), как улучшить и при этом не испортить: сначала разбор нынешних экранов на копии базы (что мешает, что работает), варианты с обоснованием, решение автора, потом правки; горячие клавиши, автосохранение, «Выдать» и обход экранов `layout.spec` — не ломать;
- **План 6:**
  - реквизиты и тексты договоров уже в настройках, в них может остаться HTML MyWork 2; размер штрихкода `[ACTS] BarcodeH/BarcodeW` и шаблоны `Shablon_*.htm` — в `legacy_rows`;
  - знак валюты из «Общие» (`currency_symbol`) хранится, но не применяется: суммы всегда с ₽ (`formatMoney` по умолчанию) — применить его по всей программе и в печати, затем поправить подсказки `ru.help.general.currency`, `firmName` (печатные формы) и текст о доле мастера, где сейчас сказано «только хранится».
- **План 8:**
  - склад из `legacy_rows` (`Stock`, `StockMap`, `settings/Stock/*.txt`) и фото `attachments/stock/<id>/` — перенос в таблицы склада в импорт и для уже импортированных баз;
  - `Zatrati` заказов уже включают запчасти из `StockMap` — не задвоить;
  - подсказка «Расходы» (`ru.help.order.extraCosts`) говорит, что сумма только хранится, — поправить, когда расходы войдут в расчёты;
  - отчёты по источнику — группировать без учёта регистра;
  - `backupPath`, `EveryDayBackup` из `legacy_rows`.
- **План 9:**
  - повторный импорт с заменой на PostgreSQL (копия — экспортом в SQLite); импорт на удалённый сервер — загрузка папки или архива;
  - за обратным прокси ограничитель попыток видит адрес прокси — нужен список доверенных прокси и `X-Forwarded-For`;
  - ограничитель считает IPv6 по одному адресу (/128) — для сервера в интернете считать по /64;
  - режим хоста (`0.0.0.0`) отключает режим без входа — интерфейс должен предложить создать администратора;
  - сервер на loopback за обратным прокси (nginx передаёт `Host` своего upstream) пропускает проверку `Host`, и режим без входа становится доступен снаружи — отказывать в режиме без входа при `Forwarded`/`X-Forwarded-For` или требовать пользователей;
  - попытка входа, отменённая по таймауту или обрывом соединения, остаётся засчитанной — нужен страж, прощающий попытку, если пароль не проверялся;
  - HTTPS и закрепление сертификата.
- **План 11 (релиз):**
  - восстановить доступ из самой программы для компьютера, если после импорта никто не может войти: сейчас выход — только `mw-server create-admin`, а у программы для компьютера командной строки нет;
  - в заметках к первому релизу сказать:
    - выдача по умолчанию требует итоговую цену, мастера и выполненные работы (настройка «Обязательно при выдаче» в «Настройки → Заказы»), в том числе через API;
    - массовая выдача пропускает заказы без цены (и без остального из набора) и называет их: «Не удалось у N заказов: № … — заполните: …»;
    - код ошибки для незаполненных мастера и работ при выдаче сменился с `required` на `required_for_issue`.
- **Общее:**
  - справочники уже перенесённой базы из её заказов (кнопка «Добавить из заказов» в «Настройки → Справочники») не делались: перенос MyWork 2 собирает справочники из заказов сам (план 5.8), автор переносит базу заново; вернуться, если понадобится без повторного переноса.
  - добавить в CI `cargo-deny` (лицензии и уязвимости зависимостей) — сейчас лицензии проверяются вручную.
  - даты в OpenAPI помечены `format: date-time`, но в API это местное время без смещения — клиент не должен добавлять `Z`/смещение;
  - ограничитель входа и e2e `--repeat-each`: прогон даёт около 4 неудачных входов, предел — 20.
  - на телефоне в списке клиентов нет множественного выбора: объединение — через «Объединить с…» (учесть в плане 10).
