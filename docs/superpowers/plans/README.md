## Заметки для следующих планов

- **План 5.4 (настройки и справочники):**
  - смена вида статуса, которым уже пользуются заказы, предупреждает;
  - гарантия: `warrantyUntil` (`intake/draft.ts`) считает месяцами любую единицу, кроме дней — при новой единице поправить;
- **План 5.5 (доводка заказов, клиентов и фото):**
  - ширины и порядок колонок, `BlistColor`, `colorDiagnostik`, `colorCheckBox`, `Poloski` из `legacy_rows` (`Config.ini`);
  - доводка интерфейса:
    - `StatusPicker`: нет «Ещё ▾» при более чем 7 статусах;
    - фото и файлы: «Повторить» у неудавшейся загрузки обходит предел в 10 фото и блокировку; «Отмена», обновление и подстановка клиента оставляют фото старого ключа до очистки через 24 ч;
    - `POST /orders` теперь помечает повтор заголовком `X-MW-Replayed: 1` — приём (`server.mjs`, интерфейс) его пока не использует;
    - кэш адресов вложений держит 25 МБ оригиналы и миниатюры под одним пределом 200;
    - клиенты: объединённый или удалённый клиент по `?client=` даёт бесполезное «Повторить»; панель показывает прежнего клиента, пока грузится следующий; созданный заказ перечитывает первую страницу клиентов;
    - окно объединения: до 20 запросов на открытие (в элементах списка уже есть `orders_count`);
    - объединение: если вместе больше 10 телефонов (`MAX_CLIENT_PHONES`), сервер отвечает 422, а убрать лишние в окне нельзя — сказать об этом до подтверждения;
    - удаление фото не отменить (журнал не вернёт файл) — «Отменить» в уведомлении с отложенным удалением;
  - после плана 5.3:
    - `scale.spec` считает элементы по классу `.label` — заменить на роль или текст; шпионы в `prefs-effect` снимать в `afterEach`;
    - регэксп `matchMedia` в `no-width-media` видит только литерал (не переменную с запросом); цифровая клавиатура принимается для всех цифр, а не только для клавиш размера;
    - `seeded ??=` в `layout.spec` кэширует отклонённое обещание (одна неудача засева роняет все случаи воркера);
    - `14rem` и класс `.btn.named` в верхней панели, ширины панелей `28rem`/`64rem` — в токены;
    - проверки обхода видят только то, что на экране: тела панелей и окон не докручиваются;
    - при сенсорном экране размеры `2.75rem` в компонентах (кнопки, поля, сегменты, меню) — литералы: при 90 % они 39.6px; перевести на `--control-*` (они уже `max(2.75rem, 44px)`);
    - обход экранов не включает сенсорный режим (`hasTouch`/`isMobile`): размеры `pointer: coarse` не проверяются; подсказка с полным заголовком карточки на сенсорном экране не открывается.
  - после плана 5.4:
    - `seen_ids` проверен на уровне API только для статусов; `putOrder` повторяет и после 403/500 (лишний запрос);
    - пользователю без права настроек интерфейс всё равно запрашивает счётчики (403 в консоли) — не запрашивать при `!can`.
    - «привести написание в заказах к справочнику»: регистр и пробелы в заказах остаются как были, если в справочнике уже нужное написание (Ruling R11); переименование с той же строкой при повторах разного регистра даёт дубль — путь через объединение (t3c);
    - гарантия: замена в заказах отклоняется, если меняет срок; если понадобится менять срок только у невыданных заказов — отдельное действие с подсчётом в окне;
    - `StatusColorButton` закрывается на каждой стрелке в палитре — оставлять открытым до Enter/Esc;
    - образ CI `mcr.microsoft.com/playwright:v…` должен совпадать с версией `@playwright/test` в `package.json` — добавить проверку (скрипт или шаг CI), а не помнить; имена обязательных проверок CI сменились (защиты ветки нет);
    - «Статусы»: `{#key redraw}` пересоздаёт все `Select` строки, и фокус уходит; текст предупреждения о смене вида берёт живой счёт, а не счёт на момент открытия окна;
    - «Статусы» и «Точки»: повторное перемещение после отказа (`reapplyMove`) возвращает удалённый тем временем id (ограничено, откат и уведомление); добавление — один и тот же поток в двух экранах;
    - «Общие»: «Следующий номер заказа» — уход из поля, пока идёт сохранение, игнорируется (введённое ждёт следующего ухода), ветка ошибки перезаписывает более новый ввод; `Number(raw)` без верхней границы и общий текст ошибки; номер не загружается, если право появилось после открытия;
    - «Общие»: в свободном режиме часового пояса (без `Intl.supportedValuesOf`) после паузы уходит недописанный пояс, сервер отвечает ошибкой; `SaveNote` молчит, когда ошибки только у полей;
    - сквозные тесты настроек: окно номера заказа ломается при 100 и больше чужих заказов за время теста; значения прогона из `Math.random`; при нескольких статусах «Выдан» проверка последнего пропускается;
    - «Справочники»: состояние переименования в двух переменных; запрос в `resolve()` собран вручную; архивные строки — отдельный `ul` вне сортируемого списка.
- **План 5.6 (десктоп, первый запуск, импорт):**
  - десктоп запускает сервер через `mw_server::Server` на `127.0.0.1:0` и раздаёт интерфейс; логи в файл в папке данных;
  - экран отчёта импорта (`legacy_imports.report`) и запуск импорта из интерфейса — выбор папки Tauri-командой, долгая операция с прогрессом;
  - импорт командой при запущенном сервере оставляет у сервера старый кэш настроек — перезапуск; импорт из интерфейса идёт в процессе сервера;
  - импорт в процессе сервера — в отдельной задаче (`tokio::spawn` + `spawn_blocking` для файлов): отменённый запрос во время записи удаляет промежуточную папку;
  - e2e: обработчики сигналов в `server.mjs` ставятся после `create-admin`; SIGKILL оставляет `mw-server` сиротой;
  - переезд окна между мониторами с одинаковым DPR не меняет «Авто» до `resize`/`focus` в WebKit — в Tauri слушать `onMoved`/`onScaleChanged`;
  - масштаб страницы в браузере (Ctrl + колесо) меняет `screen.width` в Chromium, а с ним «Авто» — в Tauri масштаб страницы выключен.
- **План 6:** реквизиты и тексты договоров уже в настройках, в них может остаться HTML MyWork 2; размер штрихкода `[ACTS] BarcodeH/BarcodeW` и шаблоны `Shablon_*.htm` — в `legacy_rows`.
- **План 8:**
  - склад из `legacy_rows` (`Stock`, `StockMap`, `settings/Stock/*.txt`) и фото `attachments/stock/<id>/` — перенос в таблицы склада в импорт и для уже импортированных баз;
  - `Zatrati` заказов уже включают запчасти из `StockMap` — не задвоить;
  - отчёты по источнику — группировать без учёта регистра;
  - `backupPath`, `EveryDayBackup` из `legacy_rows`.
- **План 9:**
  - повторный импорт с заменой на PostgreSQL (копия — экспортом в SQLite); импорт на удалённый сервер — загрузка папки или архива;
  - за обратным прокси ограничитель попыток видит адрес прокси — нужен список доверенных прокси и `X-Forwarded-For`;
  - ограничитель считает IPv6 по одному адресу (/128) — для сервера в интернете считать по /64;
  - режим хоста (`0.0.0.0`) отключает режим без входа — интерфейс должен предложить создать администратора;
  - сервер на loopback за обратным прокси (nginx передаёт `Host` своего upstream) пропускает проверку `Host`, и режим без входа становится доступен снаружи — отказывать в режиме без входа при `Forwarded`/`X-Forwarded-For` или требовать пользователей;
  - попытка входа, отменённая по таймауту или обрывом соединения, остаётся засчитанной — нужен страж, прощающий попытку, если пароль не проверялся;
  - HTTPS и закрепление сертификата.
- **Общее:**
  - добавить в CI `cargo-deny` (лицензии и уязвимости зависимостей) — сейчас лицензии проверяются вручную.
  - даты в OpenAPI помечены `format: date-time`, но в API это местное время без смещения — клиент не должен добавлять `Z`/смещение;
  - ограничитель входа и e2e `--repeat-each`: прогон даёт около 4 неудачных входов, предел — 20.
  - на телефоне в списке клиентов нет множественного выбора: объединение — через «Объединить с…» (учесть в плане 10).
