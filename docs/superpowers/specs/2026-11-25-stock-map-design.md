# Карта склада — проект решения (план 8.6)

Дата: 2026-11-25. Основа — спека `2026-11-11-mywork3-crossplatform-design.md` §5.5, дизайн-система `2026-11-15-ui-design-system-design.md` (раздел «Склад»), план 8.1 «Склад».

Автор поручил решать самому и записывать варианты (память проекта, «Работа без вопросов»). Всё ниже — решения Claude; отвергнутые варианты записаны, чтобы автор мог передумать.

## Зачем

Мастер ищет запчасть и сразу видит, где она лежит: «Дисплей Samsung A51 — B-2-4, 3 шт.». Новая партия кладётся в ячейку одним действием. На ячейке — наклейка со штрихкодом: сканер в поле поиска склада показывает, что в ней лежит.

**Успех:** в мастерской с 2–6 шкафами место любой запчасти находится за один поиск, а расстановку можно менять без потери сведений о том, что где лежит.

**Не цель:** точная геометрия помещения, учёт перемещений по сканеру «ячейка → товар», место устройств клиентов.

**Провал, даже если работает:** количество в ячейках расходится с остатком склада; удаление шкафа или уменьшение сетки молча теряет, что где лежало; коды на уже наклеенных наклейках меняются без предупреждения.

## Подходы к карте

1. **Свободный план помещения** — шкафы двигаются по холсту (x/y, масштаб). Похоже на комнату, но это тяжёлый редактор: перетаскивание на холсте, касания, масштаб, телефон. Компонента нет в дизайн-системе. Для 2–6 шкафов пользы мало. **Отвергнут**, записан в «Идеи».
2. **Шкафы карточками по порядку** (дизайн-система: «шкафы сеткой ячеек, справа свойства выбранного, переключатель „Изменить расстановку“»). Каждый шкаф — сетка: полки сверху вниз, ячейки слева направо. Порядок шкафов задаётся. Шкафы разбиты по точкам обслуживания. Просто, читается на телефоне, повторяет готовые приёмы (порядок строк, панель справа). **Выбран.**
3. **Только текстовое поле «Место» у позиции.** Дёшево, но нет подсветки, наклеек и защиты от потерь при перестановке. **Отвергнут.**

## Решения

1. **Шкаф** (`stock_racks`): код, подпись, полки (1–20), ячейки на полке (1–20), до 100 ячеек в шкафу, точка обслуживания (необязательно), порядок.
   - Код шкафа: 1–8 знаков, только латинские буквы A–Z и цифры, хотя бы одна буква. Хранится заглавными, уникален во всей базе.
     - Латиница — потому что Code 128 строится только из ASCII.
     - Хотя бы одна буква — чтобы код не путался с номером позиции.
     - Уникален во всей базе, а не в точке, — чтобы скан кода был однозначным.
   - Подпись: до 100 знаков, может быть пустой («Дисплеи»).
2. **Ячейка** — место в сетке шкафа (полка, ячейка); отдельной таблицы ячеек нет.
   - Код ячейки строится из кода шкафа: `B-2-4`, при одной ячейке на полке — `B-2`, при одной полке — `B-4`, при одной ячейке во всём шкафу — `B`.
   - Позиция (полка, ячейка) не меняется, когда сетка растёт.
   - Переход сетки между «1» и «больше 1» по любой оси или смена кода шкафа меняет коды ячеек. Экран предупреждает: «Коды ячеек изменятся — перепечатайте наклейки шкафа». Журнал записывает.
   - Формат кода не настраивается (спека допускала настройку — отложено в «Идеи»).
3. **Где лежит** (`stock_places`): позиция склада, шкаф, полка, ячейка, количество ≥ 1; одна строка на пару «позиция — ячейка».
   - Сумма по ячейкам не больше остатка (`quantity`). Разница показывается как «Не разложено».
   - Положить или переложить больше, чем не разложено (или чем лежит в ячейке-источнике), — ошибка `places_exceed`: «Столько нет — не разложено N шт.».
4. **Остаток уменьшился** (правка количества, списание в заказ, удаление позиции):
   - сначала тратится «не разложено»;
   - если сумма по ячейкам всё равно больше остатка, лишнее снимается с ячеек по порядку кодов;
   - при удалении позиции её места удаляются.
   - Что снято, записывается в подробности той же записи журнала (`stock.updated`, `order.part_added`, `stock.deleted`) полем `places_reduced`.
   - Возврат запчасти из заказа увеличивает остаток, и вернувшееся идёт в «Не разложено».
5. **Перестановка без потерь.**
   - Шкаф с хоть одной занятой ячейкой не удаляется. Сетка не уменьшается, если исчезающие ячейки заняты. Отказ называет ячейки: «В ячейках B-3-2, B-3-3 лежат запчасти — переложите их».
   - Пустой шкаф удаляется насовсем.
   - Объединение и деление ячеек, история версий расстановки — отложены в «Идеи». Журнал записывает каждое изменение шкафа (`stock_rack.created/updated/deleted`, в подробностях было/стало).
6. **Поиск по месту.**
   - У списка склада новый параметр `place`: код шкафа или ячейки, без учёта регистра. Шкаф даёт все позиции, лежащие в любой его ячейке.
   - Если строка поиска целиком совпадает с кодом шкафа или ячейки, список отвечает как с `place`: сканер наклейки вводит код в поле поиска. Экран показывает «Место B-2-4» и ссылку «Искать как текст» — тот же запрос с `as_text=true`, без подмены.
   - Совпадение проверяется без учёта регистра и ещё раз после перевода русской раскладки в латинскую по положению клавиш (ЙЦУКЕН → QWERTY). Сканер при русской раскладке вводит «И-2-4» вместо «B-2-4». Таблица соответствия — в `mw-domain`, без ввода-вывода.
   - В `search_text` коды не попадают — `SEARCH_INDEX_VERSION` не меняется. Иначе «2» в «B-2-4» находило бы позицию № 2.
7. **Где показывается место.**
   - Панель позиции: блок «Где лежит» — строки «B-2-4 · 3 шт.» и «Не разложено: 2». Действия: «Положить…» (выбор ячейки и количества), «Переложить…», «Убрать из ячейки».
   - Новая позиция («Добавить на склад»): необязательное поле «Ячейка» (код из списка). Если оно заполнено, всё количество сразу ложится в эту ячейку — новая партия раскладывается одним действием. Для прибавки к имеющейся позиции после правки количества у «Не разложено: N» стоит кнопка «Положить…».
   - Список склада: столбец «Место» (видимый по умолчанию, коды через запятую).
   - Подбор запчасти в заказ: место у строки.
   - Запчасти заказа: место у строки (текущее место позиции).
8. **Карта** — вкладка раздела «Склад»: «Список | Карта», вид в адресе `?view=map`.
   - Сверху выбор точки, если шкафы есть в разных точках.
   - Шкафы карточками по порядку. В ячейке — код и число позиций; занятая ячейка отличается не только цветом.
   - Поиск подсвечивает ячейки с найденными позициями.
   - Нажатие на ячейку открывает справа панель «Ячейка B-2-4»: что лежит, «Положить сюда…», «Печать наклейки».
   - Режим «Изменить расстановку» (право `stock_edit`): добавить шкаф, изменить (код, подпись, полки, ячейки, точка), удалить, порядок кнопками «Выше/Ниже».
   - Телефон: карта и панель читаются; правка расстановки доступна, но не обязана быть удобной.
9. **Наклейки** — новый вид документа «Наклейка ячейки» (`cell_sticker`), в конце `DocumentKind::ALL`, не для заказа, редактируемый, правила этикетки.
   - Поля: `{ячейка.код}`, `{ячейка.шкаф}` (подпись шкафа), `{ячейка.полка}`, `{ячейка.номер}`.
   - Штрихкод — код ячейки (Code 128); QR — блоком со ссылкой `{ячейка.код}`.
   - Стандартный шаблон: крупный код, подпись шкафа, штрихкод во всю ширину.
   - Печать: «Печать наклейки» у ячейки; «Наклейки шкафа» — наклейка самого шкафа (код шкафа, подпись) и всех его ячеек, одна страница на наклейку, одним заданием.
   - Меню «Вставить поле» у наклейки ячейки показывает поля ячейки и фирмы; у видов для заказа поля ячейки не показываются.
10. **Права.** Новых прав нет, миграции данных нет.
    - Карта и места — `stock_view`.
    - Расстановка и раскладка — `stock_edit`.
    - Печать наклеек — `stock_view`.
11. **Импорт MyWork 2.** В MyWork 2 мест не было: импорт не меняется.
12. **Вне плана** (в README «Идеи»): свободный план помещения; объединение и деление ячеек; история версий расстановки; настраиваемый формат кода; сканер «ячейка → товар = перемещение» (план 10, камера); место устройств клиентов («Выдача-3», стол мастера).

## Что оставлено исполнителю

Вёрстка карточки шкафа и ячейки в рамках токенов и полос ширины; тексты кнопок и подсказок, кроме перечисленных; порядок полей в диалогах.
