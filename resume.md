## 1. Проект за одну минуту

- **Что это.** Новая кроссплатформенная (Windows, macOS, Linux) программа учёта для сервисного центра по ремонту
  техники. Она заменяет старую WinForms-программу автора MyWork2 (C#, 2015–2022, ~27 тыс. строк, ей пользуются до
  сих пор). Рабочее название — **MyWork 3**, в интерфейсе пока «MyWork2». Настоящее название автор выберет позже;
  в коде нейтральное `mw`.
- **Для кого.** Приёмщик и мастер, весь день за программой; с телефона — найти заказ, сменить статус, сфотографировать,
  позвонить. Программа бесплатная, открытый код (MIT), для любых сервисов.
- **Главный риск** — перенос старых баз без потерь (сделан в плане 3 и проверен на реальной базе автора).
- **Репозиторий:** https://github.com/Scryptor/MyWork2 (публичный). Локально — `/Users/scrypto/dev/MyWork2`.
- **Стек:**
  - ядро и сервер — Rust 1.95 (edition 2024), Axum, SeaORM 2 + sqlx 0.9; SQLite по умолчанию, PostgreSQL для
    сервера;
  - интерфейс — SvelteKit 3 (SPA) + Svelte 5, bits-ui, Inter, Playwright;
  - оболочка — Tauri 2 (с плана 5);
  - документы — Typst (план 6).
- **Главное правило архитектуры:** интерфейс всегда ходит в сервер по HTTP API, даже локально: встроенный сервер на
  `127.0.0.1`.

## 2. Как работать с автором (важнее всего)

- **Язык — русский.** Автор пишет коротко и по делу («че дальше?», «Давай план 4»). Отвечать коротко, простым языком,
  без жаргона процессов.
- **Технические решения принимаешь сам**, а автор утверждает направление. Он прямо говорил: «Пиши сам, выбирай под
  себя», «Думай сам», «сам определись как лучше, удобнее, понятнее».
- **После утверждения плана — без вопросов и подтверждений**: довести до результата, спорные места решить самому и
  записать решение (в журнал выполнения и в итоговый отчёт «Решения, которые я принял»). Спрашивать только о
  необратимом или внешнем, если это не разрешено заранее.
- **Экономия токенов.** Автор упирается в 5-часовые лимиты, поэтому не показывать ему макеты и не делать лишних
  кругов («Мне можешь не показывать, чтобы токены не тратить»). Дизайн плана 4 он поручил целиком.
- **GitHub.**
  - После каждого слияния в `main` сразу делать `git push origin main`, не спрашивая.
  - Рабочие ветки без нужды не пушить. Нужда есть, когда надо прогнать CI до слияния.
  - Релизы — теги, начиная с `v0.1.0`.
  - Старый код в `legacy/` публикуется как есть: «нечего скрывать».
- **Текущее указание автора:** после завершения плана 4 **остановить разработку и доложить**. План 5 не начинать,
  пока автор не скажет.
- **Решения автора по продукту** (подробно — в основной спеке):
  - три режима: локально (SQLite), хост в сети (главный ПК поднимает API), выделенный сервер (PostgreSQL) с переносом
    данных;
  - кириллица без учёта регистра;
  - полноценный редактор актов, по умолчанию 2 акта на листе A4 (сервису и клиенту);
  - поддержка термопринтеров;
  - доступ с телефонов (PWA);
  - фото при приёме: веб-камера, телефон по QR, файлы;
  - редактор карты склада: шкафы A/B/C с ячейками, расстановка меняется;
  - светлая и тёмная темы, переключатель запоминается на устройстве; палитру выбирает Claude;
  - главный экран — «вариант A»: панель заказа выезжает справа поверх страницы.
- **Чего не делаем:**
  - SMS — позже автор сделает своё Android-приложение;
  - активацию и лицензии — программа бесплатная;
  - отслеживание Почты России.

## 5. Как проверять

- **Rust** (корень):
  `cargo fmt --all --check && cargo clippy --workspace --all-targets -- -D warnings && cargo check --workspace && cargo test --workspace`.
- **PostgreSQL в тестах:**
  - контейнер `docker start mw-pg`; если его нет — `docker run -d --name mw-pg -e POSTGRES_PASSWORD=postgres -p 55432:5432 postgres:17`;
  - затем `MW_TEST_PG_URL=postgres://postgres:postgres@localhost:55432/postgres cargo test --workspace`.
  - Сейчас контейнер остановлен.
- **Интерфейс:** `cd apps/ui && npm ci && npm run verify && npm run test:e2e`. `verify` — это svelte-check, Prettier,
  ESLint, Vitest, сборка и лицензии. Первый раз нужно `npx playwright install chromium webkit`. Node ≥ 22.17
  (локально 26, в CI 24).
- **Витрина:** `cd apps/ui && npm run dev` → `http://localhost:5173/design`, демо — `/design/orders`, `/design/intake`.
- **После изменения API:** `MW_UPDATE_CONTRACT=1 cargo test -p mw-api --test contract -- --test-threads=1` (подробности —
  в AGENTS.md).

**Интерфейс (план 4)**
- Решения по дизайну — в спеке интерфейса, раздел 11.
  - Палитра — тёплые серые и бирюза. `#0b7a6d` для кнопок, а не `#0e8a7b`, ради контраста 4,5:1.
  - Шрифт — Inter (лицензия OFL разрешена только для шрифтов).
  - Основной текст 14px, масштаб в 4 шага.
  - Панель заказа без затемнения, широкая панель приёма — с затемнением.
  - Таблица своя, на TanStack Virtual.
  - Статусы — 12 именованных оттенков.
- SvelteKit 3 (вышел в октябре 2026):
  - настройка в `vite.config.ts`, `svelte.config.js` нет;
  - `$lib` нет — импорты `#lib/...` с расширениями `.js` и `.svelte`;
  - типы API — `import type` из `$api/...`;
  - TypeScript строго 6.0.x: TS 7 не поддерживают svelte-check и typescript-eslint.
- bits-ui 2.21:
  - подсказка вешается через `children(props)` на сам фокусируемый элемент;
  - открытая подсказка внутри модального окна ставит ловушку фокуса на паузу;
  - bits-ui вызывает `preventDefault` на своём Esc, поэтому стек `layers` отступает;
  - `layers.open(...)` внутри `$effect` вызывать только через `untrack`. То же для методов `toast`.
- WebKit (macOS и Linux) теряет каретку, если поле получило фокус во время фокусировки после навигации SvelteKit.
  Поэтому широкие панели открываются после навигации.
- Однобуквенные клавиши — через `registerHotkey`, буквы сравниваются по `code`, поэтому работают в русской раскладке.
- Сканер штрихкодов:
  - распознаётся по набору от 6 символов не дольше 35 мс между ними;
  - 12 цифр — штрихкод, 13 с ведущим 0 — тоже штрихкод;
  - 1–7 цифр — номер заказа, но 5-значные номера с меньше чем 6 символами сканером не распознаются; это записано в
    спеке.
- Лицензии: проверяется дерево `dependencies`. MPL разрешена только для инструментов сборки — сейчас `lightningcss`,
  минификатор CSS в Vite.
- CI предупреждает, что `actions/checkout@v4` и `setup-node@v4` работают на Node 20, а он устаревает, и что
  `ubuntu-latest` переходит на Ubuntu 26. Обновить при подготовке релиза (план 11).

Задачи 1–10 выполнены по одной: исполнитель-субагент, затем проверяющий, затем раунды исправлений. После них —
общая проверка всей ветки и одна волна исправлений по ней. Самое важное из неё: поле суммы при Alt+↑/↓ записывало
число в соседний заказ, а в WebKit по Esc теряло набранное. Исправлено, на это есть тесты в обоих движках.

**Решения, принятые Claude по ходу плана 4.** Подробности — в спеке интерфейса (раздел 11) и в заметках дорожной
карты.

1. **OFL-1.1 только для шрифтов** (`@fontsource*`). Если неверно — заменить шрифт.
2. **`lightningcss` (MPL-2.0) исключён по имени из проверки лицензий.** Это минификатор CSS в Vite, в программу он
   не попадает. Если неверно — `build.cssMinify: 'esbuild'` и убрать исключение.
3. **`svelte-toolbelt` засчитан как MIT**: в `package.json` нет поля лицензии, но файл LICENSE — MIT.
4. **`npm overrides`: `runed` → наш Kit 3** (runed просит Kit 2 как необязательный peer). Пересмотреть, когда runed
   обновится.
5. **`#lib/*` вместо `$lib`** (требование SvelteKit 3). `$api/*` — псевдоним в tsconfig, только для типов.
6. **Сканер.**
   - 12 цифр — штрихкод.
   - 13 цифр с ведущим 0 — штрихкод из последних 12: так сканеры отдают UPC-A в виде EAN-13.
   - 1–7 цифр без ведущего нуля — номер заказа.
   - Всё остальное — текст: в плане 5 его можно передать в поиск Ctrl K.
7. **`DateInput`** — текстовое поле `дд.мм.гггг` и календарь во всплывающем окне, а не `DatePicker` из bits-ui.
8. **Демо приёма ищет клиента по последним 10 цифрам телефона.** В `fake.ts` есть фиксированный вымышленный клиент
   с номером `70000000001`.
9. **Таблица.** Строка под курсором — `aria-current`, а `aria-selected` отражает флажок. Так требует семантика
   ARIA grid.
10. **Статусы вида «выдан» нельзя поставить напрямую.** Выбор такого статуса открывает диалог «Выдать»; у
    `StatusPicker` есть право вето. В массовом меню статусов вида «выдан» нет: дата выдачи для массовой смены — в
    плане 5.
11. **`MoneyInput` сохраняет сумму на каждом нажатии**, если набранное разбирается. Ошибка показывается при уходе из
    поля и Enter, отправка формы с ошибкой запрещена. Неверный хвост («4 O5O») оставляет последнюю верную сумму
    (4 ₽). Пересмотреть в плане 5, если будет мешать.
12. **Ветку перед слиянием прогоняли через CI на GitHub**, а `main` перематывали только после зелёного CI.
